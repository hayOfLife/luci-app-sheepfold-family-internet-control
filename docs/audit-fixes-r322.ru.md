# Sheepfold r322: квота и согласованность архивного прохода Яндекс Диска

Дата: **13.09.2026**. База: **r321, `2754677022bb42ba21b26f96bf43d07fde7a972f`**,
потомок принятого владельцем `bdb3a92`. Изменения локальные, в GitHub не отправлялись.
Основная ветка — `main`; новые рабочие ветки не создавались.

## Результат и область

Исправлены **B128–B129** в `sheepfold-yandex-disk`. Реестр содержит **129 карточек**,
а не 129 независимо подтверждённых уязвимостей. Две новые карточки подробно
объясняют причины, альтернативы и ограничения: [реестр](bug-register.ru.md).

B128: при выбранных 50 МБ ошибка чтения UCI больше не разрешает 500 МБ. Значение
по умолчанию сохраняется только для подтверждённо отсутствующей опции. `status`
не показывает 100% свободной квоты при невозможности прочитать её настройку,
а `archive-push` прекращается до облачных изменений и удаления архивов.

B129: оба отправителя имеют общий контекст секции cloud; вложенная передача не
начинает новый контекст со сменившимися реквизитами и уже выбранным старым путём.
Обнаруженное изменение запрещает следующие запросы и удаление неподтверждённого
архива. Уже выполненные операции не откатываются.

Это **локально проверенный интеграционный снимок**, не аппаратно подтверждённый
стабильный релиз. Политика доступа/D01, Android, CI workflow и исполняющие runner-
скрипты не изменены. Правило «Без ограничений» выше чёрного списка устройств для
обычного интернета и независимые запреты управления/карантина сохранены. Выпуск
пакета увеличен до 0.1.0-322, без изменения зависимостей или новых фоновых служб.

## Воспроизведение до изменения исходников

### Подмена настроенной квоты

При `quota_mb='50'` подставленная UCI-команда печатает пустую строку либо `50`, затем
возвращает ошибку. След вызова обязателен. Настоящая неизменённая r321 возвращает
квоту 500; полный status сообщает `state:"ok", quota_mb:500, free_pct:100` при пустой
моделируемой коллекции. Архивный проход после такого отказа не прекращается.

### Новые реквизиты со старой папкой

После последнего успешного MKCOL модель меняет пароль; исходная r321 отправляет
два ожидающих архива и копию конфигурации с новым паролем по прежнему `/old-root`.
Каждый PUT и HEAD записан в HTTP-трассу. Оба локальных архива исчезают, итог —
`{"ok":true,"pushed":3,"errors":0}`. Аналогично проверены изменения login/root_folder.

Это полный прежний CLI, **без предварительного исправления объявлений или замены
upload_and_verify**. Реальные файлы/архивирование и shell сочетаются с моделями
UCI/HTTP. Ни одна модель не использует настоящие секреты или обращение к Яндексу.
Подтверждается неправильное сочетание реквизитов/назначения и последующая локальная
очистка после ответа модели, не реальная передача третьей стороне.

## Почему решения ограничены именно так

Reader квоты проверяет полный снимок, отказ get и допустимые значения, а не
исправляет повреждённую конфигурацию. Автоматическая запись default обратно в UCI
могла бы затронуть чужой черновик. Числовая совместимость UI сохранена: для ошибки
используются `quota_mb:0`, `free_pct:0` вместе с `state:"error"`, не новая нулевая
настройка. `archive-push` отдельно проверяет exit до арифметики и возвращает
`quota_unavailable`. Авторизационная проба может уже выполнить чтение сети.

`yandex_transfer_begin` наследует действующий контекст или создаёт его для прямого
uploader. Сверки выполняются на границах credentials/root, probe/PROPFIND/MKCOL,
PUT/HEAD, следующих файлов и перед очисткой подтверждённого локального архива.
Отсутствующий журнал и другой выбранный backend сохраняют прежний пропуск.

Остановка предпочтительнее автоматической смены назначения посреди копирования.
Она не откатывает чужие настройки и не запускает отправку повторно с другим
аккаунтом. Контекст фиксирует `sheepfold.cloud`, не все UCI-пакеты и не
`global.log_storage`. Чтения добавляют локальную работу; её стоимость на слабом
роутере не измерена. Между проверками остаются гонки, включая ABA.

Новый поздний сценарий специально подтверждает границу: если два первых архива
уже отправлены и удалены, смена настроек во время HEAD последней копии даёт отказ
без следующих запросов, но **не восстанавливает те два архива обратно**. Уже
ушедший PUT мог изменить облачный объект. Это не распределённая транзакция.

### Промежуточные отказы не скрыты

Первый вариант нового fixture не реализовывал `uci show sheepfold`, необходимый
существующему reader пути журнала. Из-за этого даже положительные архивные тесты
останавливались на подготовке события. Добавлена только недостающая ветка модели;
production для прохождения теста не ослаблялся. Доказательства этой незавершённой
подготовки отдельно названы `baseline-fixture-show-missing`, они не являются
подтверждением дефекта продукта.

Два предварительных запуска были прерваны внешними лимитами исполнения, один из
них после успешного нового файла. Они не включены как успешные полные прогоны.
Окончательный профильный запуск штатным runner завершился целиком с exit 0;
журнал `profile-suite.log` и отдельный `profile-suite.exit` сохранены. Все файлы
в нём исполнялись последовательно в отдельных процессах.

### Зависимости выбранной области

Проверены прямые потребители изменённых credentials/root/HTTP-boundary helpers:
отдельная загрузка, архивный проход, отправка журнала и скачивание. Изменённая
карта зависимостей включает новый test-file. Writer и dispatcher проверяют, что
фоновая отправка и обработка результата остались совместимыми. Общие библиотеки
журнала, Google Drive, Android и firewall не переписывались. Их полные предметные
наборы не запускались только из-за наличия в одном репозитории.

Синтаксис изменённого shell проверяется `sh -n` и BusyBox ash, четырёх изменённых
JavaScript-модулей — `node --check`. Это не runtime всех fault-тестов на BusyBox.
Offline ESLint завершился ENOTCACHED: необходимой зависимости нет в локальном кэше.
Синтаксическая проверка не заменяет lint. Проверены 288 Markdown-файлов: ссылки и
структура исправны, это не доказательство поведения продукта. Тестовые IPK собраны штатным
builder; это не каноническая SDK-сборка стабильного релиза. В обоих распакованных
пакетах helper совпадает с исходником, имеет 0755; настоящий установочный
`sheepfold-runtime-hardening` завершился с exit 0. Установка через opkg не выполнялась.
Советник quality-plan сохраняет предупреждение о размере legacy-скрипта; перенос
всего модуля ради порога увеличил бы область изменений и здесь не выполнялся.

## Повторение

Рабочая папка — корень проекта; нужны Node.js, Python 3, POSIX sh, awk и обычные
файловые утилиты. На Linux используется настоящий flock, на Windows применяется
явно обозначенная модель без доказательства kernel-блокировки. Реальные аккаунты
не требуются. Не запускать production-скрипт напрямую вместо fixture: он
предназначен для роутера. Fixtures перенаправляют пути в `.build` и удаляют свои
синтетические файлы после завершения; авария может оставить тестовую папку.

```sh
node scripts/run-test-category.mjs --file yandexContextRuntime.test.mjs
node scripts/run-test-category.mjs --file yandexDiskRuntime.test.mjs --file yandexUploadRuntime.test.mjs --file yandexBackupRuntime.test.mjs --file yandexEventsRuntime.test.mjs --file yandexSyncRuntime.test.mjs --file yandexDownloadRuntime.test.mjs
node scripts/run-test-category.mjs --file logStorage.test.mjs --file logWriterRuntime.test.mjs --file portableShellAndStatus.test.mjs --file packageHardeningRuntime.test.mjs --file changeImpact.test.mjs --file testCategories.test.mjs
python scripts/build-test-ipk.py --variant all --out-dir .build/r322-packages
SHEEPFOLD_TEST_IPK="$PWD/.build/r322-packages/luci-app-sheepfold-family-internet-control_0.1.0-322_all.ipk" node scripts/run-test-category.mjs --file testIpkPermissions.test.mjs
SHEEPFOLD_TEST_IPK="$PWD/.build/r322-packages/luci-app-sheepfold-ai-support_0.1.0-322_all.ipk" node scripts/run-test-category.mjs --file testIpkPermissions.test.mjs
node scripts/checkDocumentation.mjs --all
git diff --check
```

Ожидается exit 0. `SHEEPFOLD_YANDEX_CONTEXT_EVIDENCE_DIR` включает сохранение
JSON-трасс. Для сравнения `SHEEPFOLD_YANDEX_TEST_SOURCE` указывает на каталог с
отдельной версией файла `sheepfold-yandex-disk`; fixture не изменяет этот исходник.
На старой версии ожидаются перечисленные отказы, не зелёный контроль.

## Ограничения и следующие задачи

Полный DAV XML-reader, правильный расчёт расхода, выбор кандидатов и обработка
отказов DELETE в prune остаются **R15**. Проверка квоты исправляет выбор лимита,
а не обещает его соблюдение. В новых сценариях DELETE не выполнялся. Внутренние
подавленные ошибки старой очистки не становятся автоматически видимыми; вокруг неё
проверяется именно сохранность общего cloud-контекста.

Также остаются параллельные отправители, смена `global.log_storage` во время
операции, потоковые ограничения RAM, аварийные файлы и безопасное восстановление.
Настоящий Яндекс Диск, нативные UCI/libubox, физический роутер и новые Android/SDK
не проверялись. Модель HTTP не доказывает поддержку HEAD сервисом, а сравнение
размеров по-прежнему не является checksum. В этом проходе внешние источники и
аккаунты не использовались; доказательства — исходники и исполнение стендов.

## Поставка

Поставляются main bundle с историей, ZIP исходников, этот отчёт, накопительный
реестр и архив проверок/патчей. Тестовые IPK находятся в архиве доказательств,
не объявлены стабильными установочными пакетами. Контрольные суммы внешних файлов
вынесены в отдельный `SHA256SUMS`. Новый commit публикуется только локально;
проверка bundle и независимого восстановления фиксируется в evidence.
