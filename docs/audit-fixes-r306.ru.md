# Sheepfold r306: точный поиск Google Drive и проверяемый кэш папок

Дата: 10 сентября 2026 года. База: `9f3a38c` (r305), потомок принятой `bdb3a92`.
Версия обоих роутерных пакетов: `0.1.0-306`. Изменения локальные в `main`; push
не выполнялся. Итоговые commit/tree и контрольные суммы записываются во внешнем
`delivery-verification.json`, без самоссылочного будущего hash в коммите.

## Итог и область

Исправлены **B88–B90**: разграничение точного результата поиска и отказа, передача
имён в запросах Drive, безопасное чтение и публикация кэша папок. В
[реестре](bug-register.ru.md) **90 карточек**; это не число отдельных уязвимостей
или тестов. Проверялся `sheepfold-google-drive`, а не содержимое аккаунта владельца.

Изменены один production shell-файл и PKG_RELEASE. Расширен существующий
`tests/googleDriveUploadRuntime.test.mjs`: HTTP-двойник разбирает форму GET,
JSON-двойник поддерживает обход массива. Общие fixtures, карта зависимостей,
workflow, runner, Android и правила доступа не менялись. Прежние 70 сценариев
OAuth/загрузки сохранены. D01 и независимые границы администрирования/карантина
не затронуты. Используются уже предусмотренные curl/jshn и файловые утилиты;
новых зависимостей нет.

## B88. Поиск принимал отказ за отсутствие объекта

Старые `find_folder_id`/`find_file_in_folder` разбирали compact JSON регулярными
выражениями, подавляли неуспешное завершение запроса и не различали отсутствие
объекта с невозможностью его найти. `ensure_folder_id` после любого отказа
переходил к созданию. Аналогично upload выбирал новый POST вместо обновления.

**Обычный сценарий:** HTTP-модель возвращает корректный JSON с пробелами после
двоеточий. Оригинальная r305 создаёт уже найденные папки и выбирает создание
нового файла вместо PATCH. Никакой предварительный production-патч не применялся.
Это зафиксированные команды к модели, не реально созданные дубли в Google.

**Отказы и неоднозначности:** HTTP 403/500, curl exit 7 с внешне правильным телом,
повреждённый JSON, неправильные типы/ID, несколько совпадений и указатель следующей
страницы не давали основания выбрать произвольный ID или начать создание. Старый
код тем не менее мог продолжить. Greedy regex также выбирал вложенный посторонний
ID вместо ID элемента `files`.

Теперь результат имеет отдельные коды: 0 — один проверенный ID, 4 — доказанно
пустой полный ответ, 1 — ошибка/неоднозначность. Только код 4 разрешает создание.
Проверяются завершение curl, HTTP 200, чтение и размер JSON, массив `files`, типы,
ID, `incompleteSearch` и `nextPageToken`. Поиск файла исключает папки. Получение ID
после создания папки также проверяет HTTP, exit, JSON и безопасный формат ID.

**Почему:** регулярка с дополнительными пробелами не становится JSON-парсером.
Одного `curl --fail` недостаточно для структуры, полноты и однозначности. Выбор
первого совпадения способен обновить не тот объект. Автоматическое слияние или
удаление старых дублей не вводилось. При неполном поиске операция явно отказывает,
а не изображает отсутствие объекта. Полная пагинация осталась отдельной задачей.

**Граница:** если `nextPageToken` есть, операция отказывает даже при одном/нуле
элементов текущей страницы; это консервативный отказ, не поддержка всех страниц.
Проверка тела 64 КиБ выполняется после получения, не является потоковой RAM-квотой.
После сетевого отказа создания нельзя доказать, что сервер ничего не создал.
Конкурентные процессы всё ещё могут одновременно выполнить search-then-create.
Нативный jshn не запускался: модель его типов/массивов сверена с исходниками.

## B89. Специальные символы меняли поисковое выражение или URL

Прежнее кодирование заменяло пробелы и кавычки, но не корректно отделяло синтаксис
Drive от URL. Имя с `'`, `\\`, `&`, `+`, `%`, `#` могло разбить параметр `q`, изменить
его значение или смысл. В тесте фиксируются конечные раскодированные параметры,
а не только наличие флага curl; проверены и root_folder, и имя отправляемого архива,
включая UTF-8. Исходная r305 не передавала заданные значения без искажения.

Теперь сначала экранируется строковый литерал языка Drive, затем curl выполняет
URL-кодирование через `--get --data-urlencode q@file`. Отдельными параметрами
передаются `fields` и `pageSize`; имя не может добавлять соседние параметры.
Неподдерживаемые управляющие символы/слишком длинное имя отклоняются до HTTP.

Связанный подтверждённый сценарий: ошибка чтения существующего `root_folder`
через UCI незаметно выбирала `/sheepfold`. Теперь значение по умолчанию используется
только при подтверждённом отсутствии опции. Ошибка чтения существующей настройки
останавливает подготовку, повторный снимок обнаруживает замеченную смену секции.

**Почему:** экранирование одинарной кавычки не заменяет URL-кодирование, и наоборот.
Ручной список замен оставляет новые специальные символы. Отказ UCI не означает
решения владельца выбрать другую папку. Подтверждённое отсутствие опции остаётся
положительным контролем, а нормальные имена и пробелы не запрещаются.

**Граница:** существующий кэш папок не проверяется на соответствие новому
`root_folder` или OAuth-аккаунту. Исправлен путь, который действительно выполняет
новый поиск; полная смена контекста при старом кэше пока не решена. Один повторный
снимок UCI не создаёт транзакции всех процессов. На стороне Drive одинаковые
имена всё ещё возможны; автоматическая очистка старых дублей не добавлена.

## B90. Кэш папок записывался и читался без достаточной проверки

Старый writer записывал JSON непосредственно в `FOLDER_CACHE`, а ошибку `chmod`
подавлял. Символическая ссылка по этому имени перенаправляла запись в другой
тестовый файл, который действительно перезаписывался. Неуспешный `cat` с полным
на вид частичным выводом принимался reader как успех. Regex извлекал ID даже из
повреждённого/неполного JSON, не проверяя всю запись.

Теперь полный новый кэш сначала создаётся в уникальном каталоге с закрытыми
правами. Проверяются подготовка, запись, chmod, тип целевого объекта и публикация
готового файла через mv. Файл имеет 0600, каталог — 0700 (setgid родителя не меняет
проверяемых битов доступа). Кэш не обнуляется до готовности замены. Символическая
ссылка и каталог по целевому имени отвергаются; cleanup принадлежит только
текущему временному каталогу.

Reader проверяет успешное чтение и весь JSON: root/logs/backups — безопасные
строковые ID, root_name — строка. Нет fallback на regex или частичный stdout.
Допустимый формат с пробелами принимается. Повреждённый кэш сохранён для диагностики,
а не автоматически заменён пустыми значениями или новым поиском без оснований.

**Почему:** заключительный chmod не закрывает промежуток прямого создания с
неправильными правами. Проверить только искомое поле недостаточно для целостности
записи. Удалять прежний кэш перед публикацией опасно для восстановления после сбоя.
Отказ чтения не доказывает отсутствие файла. Проверенные отказы chmod/mv сохраняют
старое содержимое; тесты подтверждают вызов соответствующей подставленной утилиты.

**Граница:** это не общая блокировка отправителей, не гарантия против намеренной
root-подмены между проверкой и rename и не защита от потери питания. Аварийное
завершение может оставить закрытый временный каталог. Кэш — RAM-состояние; не
подтверждение сохранности резервной копии в облаке. Привязка folder cache к
реквизитам/root_folder, безопасная инвалидизация и обслуживание повреждённых
записей остаются открытыми в R14.

## Проверки и воспроизведение

| Проверка | Результат |
| --- | --- |
| Профильный runner | **192 теста в 5 файлах, все прошли**, без skips/cancelled |
| Google Drive runtime | **112**: 70 прежних + **42 новых** |
| Новые сценарии на оригинальной r305 | **38 не проходят, 4 проходят** |
| logStorage / logWriterRuntime | **4 / 34**, все прошли |
| packageHardeningRuntime | **17**, все прошли |
| Standard testIpkPermissions | **25**, все прошли; включены в 192 |
| AI Support archive checks | **25 прошли** повторно; не прибавлены к уникальным |
| Обе тестовые упаковки | r306; uploader совпадает с исходниками, 0755; hardening обеих прошёл |
| Синтаксис и документация | 1 shell через sh/BusyBox ash, 1 JavaScript, 8 Markdown — без ошибок |

Сравнение baseline выполнялось двумя группами: основная — 33 (30 fail/3 pass),
дополнительная — 9 (8 fail/1 pass). Сумма — 42 (38/4), без удвоения повторов.
Это не 38 отдельных уязвимостей. Некоторые тесты новой стадии mv/чтения файла
ответа обнаруживают отсутствие этой стадии в r305, а не вызов несуществовавшего
кода. Обычное поведение, искусственные отказы и новые защитные контроли разделены.

Первый исправленный запуск основной группы: 32/33. Оставшийся отказ связан с тем,
что `/mnt/data` наследует setgid на каталогах. Проверка требовала точное 0700 и
ошибочно считала 02700 более широким доступом. Исправлен только test assert: он,
как соседние проверки, сравнивает биты `0777`. Production не ослаблялся. Две первые
попытки foreground-запуска были прерваны ограничением инструментального вызова,
не представлены как результат теста; полные завершённые журналы сохранены отдельно.

Исполняется настоящий скрипт проекта. HTTP, UCI и jshn представлены моделями;
реальные curl-запросы к облаку не выполняются, токены синтетические. Модель HTTP
записывает точный q/метод/тело, проверяются права Linux и след fault-команды. Проверка
исходников libubox не выдана за запуск нативной библиотеки. Права и symlink-поведение
не объявляются подтверждёнными на Windows.

### Команды

Рабочий каталог — корень проекта. Нужны Node.js, Python 3, POSIX sh и файловые
утилиты. Ожидается exit 0, без сети и реквизитов:

```sh
python3 scripts/build-test-ipk.py --variant all --out-dir .build/ipk-output
SHEEPFOLD_TEST_IPK="$PWD/.build/ipk-output/luci-app-sheepfold-family-internet-control_0.1.0-306_all.ipk" \
node scripts/run-test-category.mjs \
  --file googleDriveUploadRuntime.test.mjs \
  --file logStorage.test.mjs \
  --file logWriterRuntime.test.mjs \
  --file packageHardeningRuntime.test.mjs \
  --file testIpkPermissions.test.mjs
SHEEPFOLD_TEST_IPK="$PWD/.build/ipk-output/luci-app-sheepfold-ai-support_0.1.0-306_all.ipk" \
node --test tests/testIpkPermissions.test.mjs
node --test --test-name-pattern 'Google Drive lookup' tests/googleDriveUploadRuntime.test.mjs
node scripts/checkDocumentation.mjs --git 9f3a38c
sh -n package/luci-app-sheepfold-family-internet-control/root/usr/libexec/sheepfold/sheepfold-google-drive
busybox ash -n package/luci-app-sheepfold-family-internet-control/root/usr/libexec/sheepfold/sheepfold-google-drive
node --check tests/googleDriveUploadRuntime.test.mjs
git diff --check
```

Для baseline положить оригинальный `sheepfold-google-drive` из `9f3a38c` в отдельный
каталог и передать путь в `SHEEPFOLD_GDRIVE_TEST_SOURCE`. Запуск тех же 42 тестов
должен дать exit 1 и 38/4. Не исполнять production helper напрямую вместо fixture:
он читает реальные настройки и изменяет состояние. Fixture работает только в
`.build/gdrive-fixtures`, удаляя принадлежащие ему объекты; аварийное прерывание
может оставить тестовый каталог. Прежние source/final логи сохраняются отдельно.

Полный набор не запускался. Quality plan из-за затронутых документов также
показывает общий critical/full-suite совет. Он рассмотрен, не скрыт: изменены
отчёты/реестр/описание тестов, но не глобальный контракт, test engine или правила
агентов. Производственный патч ограничен одним облачным helper; зависимости
обозримы. По критериям владельца выбран прямой контур. Эти пять файлов — рекомендации quality plan
для изменённого helper и теста. Версия пакета не стала причиной запуска Android
или всего backend. Предупреждения о длине source/test сохранены; большой перенос
всего cloud-модуля не включён в узкий патч. Проверка JS-синтаксиса не заменяет
ESLint. Команда `npm exec --offline -- eslint tests/googleDriveUploadRuntime.test.mjs`
завершилась с ENOTCACHED: зависимость отсутствует локально. Это не выполненный lint.
Структурные предупреждения: 1145 строк source (ориентир 900), 562 строки теста
(ориентир 500). Они сохранены в журнале, лимиты не повышались. Финальная проверка
поставки и повтор из bundle — во внешнем отчёте.

## Что не закрыто

R14 остаётся открытой: folder cache не связан с OAuth-аккаунтом/root_folder,
поиск/создание не являются межпроцессной транзакцией, нет полной пагинации,
контрольных сумм загрузок, независимой проверки существования cached папок и
автоматического обслуживания дублей/повреждения. Команды самостоятельного
скачивания/восстановления и старые quota/list paths не объявлены рабочими этим
патчем. Ошибка после HTTP-записи не означает гарантированного отсутствия изменений
на сервере. Автоматический повтор изменяющих запросов не добавлен.

Настоящий Google Drive/OAuth, native UCI/libubox, физический роутер, новые
Android/SDK/CI-сборки не проверялись. r306 — локальный интеграционный снимок,
а не подтверждённый стабильный релиз.

## Первичные источники внешней сверки

Проверены 10.09.2026, без доступа к личным аккаунтам:

- [Google Drive: search files](https://developers.google.com/workspace/drive/api/guides/search-files):
  синтаксис q, экранирование апострофа/обратной косой черты отдельно от URL,
  различие файлов и папок через mimeType.
- [Google Drive files.list](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/list):
  files, nextPageToken, incompleteSearch и неполные страницы. Ограничение pageSize
  само по себе не доказывает полноту ответа.
- [curl manual](https://curl.se/docs/manpage.html): --get/--data-urlencode и чтение
  значения из файла через name@file.
- [OpenWrt libubox jshn.sh](https://lxr.openwrt.org/source/libubox/sh/jshn.sh):
  json_select, json_get_keys, json_get_type и представление boolean/array.

Остальные результаты получены из локального diff и исполняемых тестов, не из
публичных страниц репозитория. Подробные карточки — [B88–B90 и R14](bug-register.ru.md).
