# ADR-0022: Временный сервисный доступ техподдержки

- Статус: Частично заменено [ADR-0031](0031-typed-https-remote-support.ru.md)
- Дата: 2026-08-23
- Теги: `§rsup001`
- Связанные документы: `docs/remote-support-access-plan.ru.md`, `docs/remote-support-threat-model.ru.md`, `docs/remote-support-protocol.ru.md`, `docs/security.ru.md`

## Контекст

Запись сохраняет первоначальный FRP/SSH-проект. Для текущей реализации его transport,
bastion и SSH forwarding заменены исходящим HTTPS/typed контрактом ADR-0031. Явное
разрешение владельца, окно claim 72 часа, доступ 24 часа и независимый отзыв сохраняются.
Упоминания `frpc` и SSH ниже не являются текущим планом установки.

Полное удалённое управление Sheepfold ранее было запрещено: постоянный VPN или публичный LuCI создаёт слишком широкую поверхность атаки. На практике владельцу может потребоваться помощь после сбоя Podkop, обновления или отключения электричества, когда роутер доступен в интернет, но обычные клиенты работают неправильно. Личный выезд специалиста не должен быть единственным способом восстановления.

## Рассмотренные варианты

1. Оставить только Telegram/VK и локальную диагностику. Безопасно, но недостаточно для сложного ремонта сети.
2. Постоянно подключить роутер к Tailscale/ZeroTier. Просто, но создаёт более широкую VPN-сеть и постоянное доверие, чем требуется одной заявке.
3. Открыть LuCI/SSH на WAN. Отклонено как небезопасное.
4. Временный исходящий reverse SSH transport через `frpc`, закрытый bastion и одноразовое разрешение владельца.

## Решение

Разрешить узкое исключение из запрета туннелей только для временной техподдержки:

- режим выключен по умолчанию и устанавливает `frpc` только после явного выбора;
- владелец создаёт 12-значный одноразовый код с окном ожидания до 72 часов;
- техподдержка входит под одной выделенной служебной учётной записью с MFA; код сам по себе не открывает роутер;
- каждый роутер имеет отдельную криптографическую identity, а transport использует короткоживущий mTLS credential вместо общего FRP token;
- после первого принятия код сгорает, а административный сеанс действует 24 часа;
- случайный server-side порт относится только к одному сеансу, доступен только закрытому bastion и не кодируется в продиктованном номере; порт не считается шифром или фактором аутентификации;
- роутер публикует только локальный SSH через закрытый bastion, не WAN-LuCI и не домашнюю подсеть;
- используется временный SSH-ключ техподдержки, а не пароль root владельца;
- канал к relay маршрутизируется отдельным Sheepfold-owned правилом напрямую через WAN и не изменяет Podkop;
- `frpc` работает под отдельным UID, а аварийный маршрут совпадает одновременно по UID, проверенному endpoint и порту;
- небольшой Sheepfold connection manager владеет подписанной multi-relay картой, failover, bounded backoff/jitter, состояниями и неизменяемыми session deadlines; FRP остаётся только транспортом;
- firewall4 reload, netifd reconnect и сбой DNS восстанавливают канал из последней подписанной карты relay, не затрагивая Podkop;
- опасные network/firewall/DNS/Podkop-изменения во время сеанса используют независимый rollback-таймер и считаются успешными только после нового heartbeat и восстановления SSH со стороны relay;
- владелец может немедленно отозвать доступ, сервер и роутер независимо соблюдают срок;
- постоянное удалённое управление Android/LuCI и произвольные VPN-туннели остаются запрещены.

Текущее состояние кода ограничено неактивной заглушкой в `Настройки -> Интеграция`: она не создаёт UCI-параметры, не устанавливает `frpc`, не вызывает backend и не открывает соединение. Рабочие элементы можно включить только после реализации и проверки протокола, router backend и server-side fail-closed состояния.

## Последствия

- Техподдержка сможет исправлять сложные сбои без личного визита, если WAN роутера работает.
- Sheepfold получает первый developer-operated control component, поэтому нужны отдельные серверная безопасность, MFA, аудит, эксплуатация и юридические тексты. Первая версия различает только одну служебную учётную запись, а не отдельных сотрудников.
- Бесплатность исходного кода FRP не означает бесплатность сервера поддержки.
- При физически неработающем WAN функция бесполезна; локальное аварийное восстановление проектируется отдельно.
- Safe-apply требует точного ownership затронутых файлов и не может обещать пережить factory reset, sysupgrade, повреждение прошивки или потерю питания.
- Два relay и warm standby повышают стоимость сервера и RAM; фактический режим выбирается только после измерения на Xiaomi AX3000T.
- Динамический IP допустим только для PoC. Боевой аварийный режим требует минимум один постоянный публичный IPv4, а полноценный failover — второй независимый relay.
- Постоянный публичный IPv4 нужен внешнему серверу Sheepfold, а не домашнему роутеру. Remote support не отключает IPv6 на роутере; существующее автоматическое отключение IPv6 относится только к совместимости с Podkop (§ipv6pod).

## Проверка

Нужны unit/integration тесты кода и срока, package ownership, revocation, reboot cleanup, подписанного протокола и отсутствия секретов. На живом роутере проверяются отсутствие входящего WAN reverse-порта, взаимный TLS, независимость кода от внутреннего порта, доступ только с bastion, отсутствие LAN routing и четыре сочетания Sheepfold с Podkop/AdGuard Home. Эти проверки не доказывают безопасность внешнего сервера; он требует отдельного аудита и эксплуатационного контроля.

## Когда пересматривать

- FRP перестал поддерживаться или исчез из официальных пакетов OpenWRT;
- измерения показывают неприемлемую нагрузку на Xiaomi AX3000T;
- Podkop предоставляет официальный безопасный bypass API;
- появляется более узкий и проверенный сервисный transport;
- требуется доступ без работающего WAN либо без явного действия владельца.
