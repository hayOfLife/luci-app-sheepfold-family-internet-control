# Аудит и исправления Sheepfold r301

Дата: **10 сентября 2026 года**. База — `fcd2dc7` (r300), потомок принятой
`bdb3a92`. Пакет **0.1.0-301**, ветка `main`. Точный итоговый commit, дерево,
контрольные суммы и проверка поставки записаны в `delivery-verification.json`
архива проверок. Push, установка на роутер и изменение внешних аккаунтов не выполнялись.

## Итог и область изменения

Исправлены четыре группы **B72–B75**. [Накопительный реестр](bug-register.ru.md)
содержит 75 карточек: воспроизведение, причину, решение, отклонённые альтернативы,
проверки и границы. Это карточки дефектов, не 75 независимых уязвимостей.

Один изменённый производственный скрипт:
`package/luci-app-sheepfold-family-internet-control/root/usr/libexec/sheepfold/sheepfold-api-legacy`.
Изменены чтение и очистка административного RAM-журнала, общий строковый JSON-
кодировщик этого скрипта и его внутренний optional legacy AI-потребитель журнала.
Публичный AI endpoint делегирует отдельному handler: проверка внутреннего legacy
пути **не является доказательством исправления текущего публичного AI-пути**.

В Makefile увеличен только release. Новых runtime-зависимостей нет. Общий
`sheepfold-lock-common` и flock уже используются записью/обслуживанием журнала
и включены в обе редакции. Android, LuCI, правила доступа, токены, workflow и
runner-скрипты не изменены. Добавлены runtime-тест и его связи в существующей
карте категорий/прямых потребителей fixture; механизм выбора не переписан.
D01 («Без ограничений» выше чёрного списка для обычного интернета) сохранён,
как и независимый запрет управления и карантин.

## Найденные дефекты и решения

### B72. Непроверенное чтение и ложный выбор журнала по умолчанию

На старом скрипте tail мог напечатать часть строки и завершиться ошибкой, а API
всё равно отвечал 200. Фильтр маскирования мог аналогично передать частичный
вывод как будто обработка закончилась успешно. Проверено фактическое достижение
обоих искусственных отказов. Это не утверждение о реальной утечке на роутере.

Отдельно UCI отказ чтения настроенного пути подменялся default. В тесте clear
обнулял default-файл вместо сообщения о недоступности пользовательского пути.
Теперь обе стадии чтения/маскирования проверяются отдельно до заголовка 200;
частичный вывод отбрасывается. GET возвращает `503 log_unavailable`. При отказе
lookup default выбирается лишь после успешного чтения конфигурации,
подтверждающего отсутствие опции. Clear при неподтверждённом пути отвечает
`500 log_clear_failed`, не трогая default и custom-файл.

Почему не пустой массив: недоступный журнал не равен отсутствию событий.
Почему не проверка только последней команды pipeline: она скрывала отказ
предыдущей. Нормальные пустой/отсутствующий журнал, предел строк и редактирование
адресов/некоторых секретных полей остаются поддержаны. Внутренний legacy AI-path
не передаёт синтетическому транспорту неподтверждённый log-context.

### B73. Выход из разрешённого каталога при чтении и очистке

Условие строкового префикса `/tmp/sheepfold/*` принимало путь с `..`.
На изолированном файле вне runtime-каталога реально воспроизведены чтение
содержимого и успешное обнуление. Ссылки также позволяли перенаправить действие.
Даже явно внешний путь без разрешённого префикса приводил к опасной подмене
на default, а не отказу от очистки.

Теперь допускается обычный файл внутри фиксированного RAM-корня. Проверяются
компоненты, root, тип и symlink, включая повтор после взятия блокировки.
Вложенные обычные каталоги и пробелы в имени не запрещены. Неправильный путь
отклоняется, никакая его часть не «исправляется» в другое имя файла.

Почему не нормализовать молча: тогда административная команда могла бы удалить
не тот ресурс, который был настроен. Проверка shell-компонентов не равна
openat/O_NOFOLLOW и не защищает от привилегированного несогласованного процесса,
подменяющего путь после проверки, hardlink или изменения mount. Настройку пути
в проверенном сценарии меняет администратор; анонимный сетевой обход не заявлен.

### B74. Невалидный JSON и потеря управляющих символов

Backspace, form feed и другие control-байты попадали в JSON буквально. Табуляция,
CR/LF заменялись пробелами. Ошибка относится к сериализатору legacy API, в том
числе его сообщениям о неудачной команде, а не к уже исправленным сериализаторам
устройств/просьб/уведомлений.

Использовано посимвольное экранирование на уже доступном awk. UTF-8, кавычки,
обратная косая черта и управляющие значения сохраняются в JSON-представлении.
Читаемый массив собирается и проверяется до успешных заголовков. Удаление
символов не выбрано: оно продолжило бы менять данные. Формат успешного ответа
`entries: [строки]` не заменён целевой схемой `/api/v1/logs`.

NUL, бинарный контент и побайтное сохранение разделяющих пустых строк не входят
в формат shell-журнала. Шаблоны маскирования сами по себе не доказывают полную
анонимность произвольного текста.

### B75. Отсутствие общей блокировки и небезопасные права нового файла

GET и clear выполнялись, пока другой процесс удерживал настоящий inode
`log-maintenance.flock`, используемый writer/maintenance. Старый clear при
обычной маске 022 создавал файл с 0644. Сбой chmod раньше не рассматривался.

Новые операции в отдельных subshell берут общий lock, освобождаемый при выходе
и обработанных сигналах. Невозможность взять lock запрещает операцию. Перед
обнулением существующего файла проверяется chmod 0600, новый создаётся сразу
под umask 077. Отказ chmod не уничтожает исходное содержимое.

Почему не удалить файл и создать новый без lock: параллельный writer мог бы
держать старый inode; отдельная новая блокировка не согласовалась бы с ротацией.
Успешная очистка действует в момент операции; следующая запись законна. USB,
Yandex и архивы не стираются. Проверен барьер реального flock, не полная нагрузка
с физической ротацией, flash и отключением питания.

## Воспроизведение и методика

`tests/legacyLogRuntime.test.mjs` содержит **43 сценария**. Используется настоящий
legacy-скрипт и отдельные проходы внешнего CGI. Файлы, авторизация, UCI и вызовы
транспорта синтетические. Применяется системный POSIX sh; подставленные tail,
sed, uci, chmod, flock должны оставить проверяемый trace. Это исключает прежнюю
ошибку вывода о fault injection без достижения подставленной команды.

Для конкурентного теста отдельный процесс захватывает реальную файловую
блокировку. Тест ждёт подтверждения готовности и попытки API взять lock, проверяет
сохранность файла до снятия барьера и результат после. Права, symlink и native
flock ограничены Linux; на Windows пропуск обозначается явно. В Linux данного
прохода пропусков нет. Внешних провайдеров тесты не вызывают.

Для baseline подменяется только производственный legacy-handler версией r300;
текущие fixture и assertions одинаковы. Это не полный запуск каждого старого
компонента. Получено **31 fail / 12 pass**. На исправлении **43/43 pass**.
Неудавшийся сценарий может проверять иной HTTP-код, а не отдельную уязвимость.
Предварительные, исходные и итоговые журналы сохранены отдельно.

## Команды повторения

Корень клона; Node.js 22, системный sh, awk/sed и файловые утилиты; Linux/flock
для native-сценариев. Тестовые IPK дополнительно требуют Python 3.

```sh
node --test tests/legacyLogRuntime.test.mjs
python scripts/build-test-ipk.py --variant all --out-dir .build/ipk-output
SHEEPFOLD_TEST_IPK_DIR="$PWD/.build/ipk-output" node scripts/run-test-category.mjs --file legacyLogRuntime.test.mjs --file apiFormRuntime.test.mjs --file readModelRuntime.test.mjs --file tokenAuthenticationRuntime.test.mjs --file maintenanceJobs.test.mjs --file lockCommon.test.mjs --file backendRuntimeSafety.test.mjs --file productVariants.test.mjs --file changeImpact.test.mjs --file testCategories.test.mjs --file packageHardeningRuntime.test.mjs --file androidRouterSessionRecovery.test.mjs
```

Для сравнения базы в отдельном новом каталоге:

```sh
git worktree add --detach ../sheepfold-baseline-r300 fcd2dc7
SHEEPFOLD_LOG_TEST_SOURCE="$(cd ../sheepfold-baseline-r300 && pwd)" node --test tests/legacyLogRuntime.test.mjs
```

Последняя команда ожидаемо завершается неуспешно на старом скрипте; это
доказательство воспроизведения, а не команда проверки готовности r301.

## Ограничения и следующая область

R13 оставляет аудит остальных log-consumers, побайтовый предел ответа/RAM,
полноту маскирования, стабильность UCI-пути и привилегированные гонки открытия.
Один общий flock координирует только процессы, которые действительно его берут.
Чтение может задержать writer в пределах своей обработки; аппаратная задержка
на слабом роутере не измерена. Другие открытые R01–R12 не объявлены закрытыми.

Новый код не установлен на OpenWrt; настоящие UCI, uhttpd, writer/ротация под
нагрузкой, физический Android, Wi-Fi, flash и отключение питания не проверялись.
Android/SDK/Actions не запускались. Синтаксические проверки не заменяют ESLint;
при отсутствии локальных зависимостей lint нельзя объявлять успешным. Сведения
о доступности инструментов и восстановлении bundle приложены отдельно.

r301 — локально проверенный интеграционный снимок, **не подтверждённый стабильный
релиз**. Принятые workflow/runner и история прошлых результатов сохраняются.
