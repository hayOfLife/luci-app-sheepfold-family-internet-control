# Безопасное обновление Sheepfold

<!-- §updsafe -->

## Граница гарантии

Updater устанавливает только более новую stable-версию выбранного варианта Sheepfold и старается не оставлять настройки в частично изменённом состоянии. Он поддерживает IPK/`opkg` на OpenWrt 24.10 и старше и OpenWrt APK/`apk` v3 на 25.12 и новее через единый адаптер (§pkgmgr1). Он **не выполняет бинарный rollback**: для такого отката нужен реально сохранённый и проверенный предыдущий пакет, которого текущая схема ещё не гарантирует.

## Переименование GitHub и допустимые адреса

10.10.2026 через GitHub API подтверждено переименование владельца `kva4991` в
`hayOfLife`. Новый канонический путь — `hayOfLife/luci-app-sheepfold-family-internet-control`.
Старый API отвечает HTTP 301, а метаданные релиза уже содержат новый путь assets.
Поэтому исправлены адрес API и строгий release-префикс одновременно; просто разрешить
произвольные перенаправления или любой GitHub-репозиторий было бы ослаблением защиты.

После префикса разрешены ровно два компонента: tag и имя пакета. Tag содержит только
ASCII-буквы, цифры, `.`, `_`, `+`, `-`, но не равен `.` или `..`; имя пакета дополнительно
допускает `~` для версий. Проценты/URL-кодирование, дополнительные `/`, обратные слеши,
query, fragment и управляющие символы запрещены. GitHub-теги со слешами или Unicode
не поддерживаются этим каналом выпуска. Старый namespace больше не разрешён.

Первоначальный `install.sh` использует ту же компактную URL-проверку до скачивания
пакета. Копия необходима до установки backend; тест сравнивает функции побайтно после
нормализации CRLF. Это **не** перенос полного валидатора IPK/APK в bootstrap:
его собственная проверка внутренних метаданных пока не реализована, остаётся проверка
системным менеджером пакетов. Не обещать одинаковые гарантии bootstrap и updater.

Уже установленный старый updater не исправляется от одной замены `origin` или загрузки
нового `update.sh`: эта обёртка запускает установленный helper. После отдельной сборки
и публикации исправленный пакет потребуется один раз установить локально с сохранением
настроек; не отключать URL/TLS-проверки и не переустанавливать старый latest ради обхода.
На дату проверки `releases/latest` всё ещё содержит старый IPK r58, не исходники r324.
Исправление в рабочем дереве не означает выпуск или установку новой версии.

## Что проверяется до менеджера пакетов

1. Ответ читается из GitHub `releases/latest`.
2. `browser_download_url` обязан вести в `https://github.com/hayOfLife/luci-app-sheepfold-family-internet-control/releases/download/` и содержать имя именно установленного варианта: Standard либо AI Support.
3. Сетевая попытка ограничена 120 секундами, файл — 64 МиБ. Реальный код `uclient-fetch`, `curl` или `wget` сохраняется.
4. Для IPK внешний gzip-tar обязан содержать ровно по одному `debian-binary`, `control.tar.gz` и `data.tar.gz` без небезопасных путей и повторяющихся файлов; `debian-binary` содержит `2.0`.
5. Для IPK в `control` допускается ровно по одному полю `Package`, `Version`, `Architecture`. Имя совпадает с устанавливаемой сущностью, версия — с release asset, архитектура — `all`.
6. Оба вложенных IPK-архива должны полностью читаться; абсолютные пути и компоненты `..` запрещены. Повторные записи каталогов разрешены, повторный файл запрещён.
7. Для OpenWrt APK выполняются `apk verify --allow-untrusted` и `apk adbdump --format json`. Из внутренних метаданных через `jshn` проверяются точные `info.name`, `info.version` и совместимая `info.arch`; проверка не полагается только на имя файла.
8. Строгий префикс OpenWrt-пакета не позволяет принять родительский или детский Android APK за пакет роутера.

Только после этих проверок единый адаптер вызывает `opkg install` или `apk add --allow-untrusted`.

## Поведение при установке

- Без участия в бета-тесте установка требует отдельного подтверждения. Исключение `beta_testing=1` явно разрешает часовые автоматические обновления из того же stable-источника; [условия и отключение](maintenance-jobs.ru.md) (§betatest1).
- Ручные и автоматические операции используют общий `update.flock`, включая `check/probe`, поскольку им нужны те же временные файлы. Занятая блокировка возвращает код `3`; в бета-режиме повтор будет через час.

- Перед установкой updater запоминает, существовал ли `/etc/config/sheepfold`, и создаёт копию с правами `0600`.
- `preinst` дополнительно сохраняет последний непустой конфиг в `/etc/sheepfold/migrations/sheepfold.config.pre-upgrade`.
- `postinst` не удаляет оперативную копию: это делает updater после того, как системный менеджер пакетов вернул результат.
- При ненулевом коде установки updater возвращает тот же код и восстанавливает прежний конфиг. Если конфиг до обновления отсутствовал, появившийся после неудачной установки файл удаляется.
- Даже после кода `0` updater повторно читает установленную версию через общий адаптер. Несовпадение считается ошибкой и вызывает восстановление конфига.
- После подтверждённой версии временный пакет и копия удаляются, затем перезапускаются Sheepfold и `rpcd`.

## Почему недостаточно `set -e`

Shell-функция, вызванная в конструкции `install_update || code=$?`, может выполняться в контексте, где `set -e` не останавливает её на каждой внутренней ошибке. Поэтому валидация, backup, установка и проверка версии имеют явные ветки возврата. Этот контракт защищён поведенческим тестом `tests/updateTransportSafety.test.mjs`; в нём отдельно проверяются IPK/`opkg` и APK/`apk`.

## Что ещё требуется

Текущая проверка доверяет HTTPS/GitHub и метаданным/целостности контейнера. `apk --allow-untrusted` не удостоверяет ключ издателя через заранее установленный keyring. Не называйте это полноценной проверкой подписи выпуска; отдельный защищённый signing/update manifest остаётся будущим усилением. Бета-режим не добавляет исключений TLS или новых ключей доверия.

- Проверка на живых OpenWrt 24.10 и 25.12 с настоящими `uclient-fetch`, BusyBox `ash`, `opkg` и `apk` v3.
- Проверка нехватки `/tmp`, обрыва питания и ошибки реального `postinst`.
- Решение о хранении предыдущего пакета и безопасном бинарном rollback. Пока архив не сохранён заранее, не повреждён и не соответствует предыдущей установленной версии, кнопку `Откатить` показывать нельзя.

## Локальная проверка адресов и обновления

Рабочий каталог: корень checkout Sheepfold, PowerShell с Node, Git Bash и Python.

```powershell
node --test tests/updateTransportSafety.test.mjs
node --test tests/installSettingsPreservation.test.mjs tests/installLanguage.test.mjs
```

Ожидаются exit 0 и `fail 0`. Первый файл исполняет настоящий updater на фиктивных
HTTP/UCI/package-manager командах, проверяет 56 сочетаний URL/формата/редакции,
ошибку скачивания, отмену beta и восстановление настроек. Только временные данные и
тестовый IPK в `.build/test-tmp` меняются; установленный роутер и GitHub не затрагиваются.
Не запускать `install.sh` или updater напрямую на рабочем компьютере ради теста.
Отсутствие `flock` даёт явный skip конкурентной проверки; Windows-модель не доказывает
BusyBox, настоящий package manager, издательскую подпись или аппаратный rollback.
При ошибке дочернего Python использовать подготовленный `SHEEPFOLD_TEST_IPK` по
[описанию окружения](agent-environment.ru.md), не выключать проверку пакета.
