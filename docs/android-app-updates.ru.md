# Ручное обновление родительского APK

<!-- §apkupd1 -->

Экран: родительский APK → «Информация» → «Обновление приложения». Это отдельная кнопка,
не обновление данных роутера и не бета-обновления OpenWrt. Детский APK пока не включён.

## Текущее состояние

Реализованы проверка релизов, ограниченное скачивание, проверка APK и передача системному
установщику Android. Переход между двумя опубликованными production-версиями ещё не проверен.
31.08.2026 в существующий экспериментальный релиз добавлен тестовый родительский
`0.1.58` / code `59`. Публичные метаданные, скачивание и подпись проверены.
На момент публикации на телефоне оставлен `0.1.57` для самостоятельной проверки владельцем.
Это debug-обновление с прежним тестовым сертификатом, а не production-выпуск.
Затем владелец сообщил о повторном предложении скачать APK после разрешения источника.
Завершённая установка на его телефоне после этого отдельно не подтверждена.
В опубликованном тестовом `0.1.59` сценарий исправлен: скачивание сразу ведёт к системному подтверждению,
возврат из настройки источника продолжает установку, а проверенный APK восстанавливается
после потери процесса. Публикация проверена 31.08.2026; физическая установка этой версии
оставлена владельцу для проверки и отдельно не подтверждена.

## Пользовательский путь

1. «Проверить обновление» запрашивает GitHub. Таймера, автопроверки при входе и WorkManager нет.
2. Экран показывает актуальную версию, доступное обновление или отсутствие подходящего APK.
   Ошибка сети не называется «Установлена актуальная версия».
3. «Скачать и установить» загружает файл с процентом и отменой, проверяет APK и сразу
   открывает системное подтверждение. Отдельное нажатие установки обычно не требуется.
4. Если Android не разрешает установку из Sheepfold, открывается настройка только этого
   источника. После выдачи разрешения и возврата установка продолжается автоматически.
   Некоторые прошивки оставляют экран настроек открытым после переключения: нажать «Назад».
   Sheepfold не закрывает чужой экран принудительно и не обходит системное подтверждение.
5. Отказ в разрешении, отмена или ошибка открытия установщика сохраняют файл и кнопку
   «Установить обновление». Автоматического повторного открытия после отказа/отмены нет.

Поворот сохраняет операцию в Activity ViewModel. Переход между вкладками не запускает второй
запрос. Системные результаты зарегистрированы в `MainActivity`, а не во временной вкладке.
Выход в Settings может уничтожить процесс: готовый файл и публичные метаданные восстанавливаются
и перепроверяются без повторного скачивания. Начатое ожидание разрешения продолжает установку
только в пределах 30 минут, при выданном разрешении и разблокированном приложении на переднем
плане. При возврате открывается «Информация». Обычный холодный запуск без такого ожидания
показывает сохранённую кнопку установки, но не открывает установщик сам.
Незаконченное скачивание после гибели процесса не продолжается. Настройки, PIN и привязка
не сбрасываются; если сработала локальная блокировка, сначала требуется её обычное снятие.

## Источник и безопасность

10.10.2026 фиксированный канал переведён с `kva4991` на подтверждённое имя `hayOfLife`.
Старый API возвращает 301; Android намеренно не следует metadata redirect, а старый
asset-префикс не принимает новые ссылки. Исправлены обе константы через единый
`ParentUpdatePolicy.repository`, без изменения TLS, SHA-256 и проверки подписанта.
`ParentUpdatePolicyTest` использует также буквальный новый URL, чтобы тест не менял
ожидаемый результат вместе с ошибочной production-константой, и отклоняет старый owner.

Это правка исходников, не опубликованный APK. Уже установленная версия
со старым каналом не сможет получить исправление собственной кнопкой: после отдельной
сборки/публикации понадобится одно ручное обновление APK с тем же подписантом и большим
`versionCode`, без удаления приложения и его данных. Старый кеш обновления с прежним URL
не мигрируется в доверенный автоматически; после обновления канала файл можно скачать заново.

- Фиксированный endpoint: `https://api.github.com/repos/hayOfLife/luci-app-sheepfold-family-internet-control/releases?per_page=20`.
- Только 20 возвращённых релизов без `draft` и `prerelease`; выбирается самая высокая
  числовая версия родительского APK. Последний релиз роутера без Android-файла не скрывает
  предыдущий родительский релиз внутри этого ограниченного окна.
- Точное имя: `sheepfold-parent-v<version>.apk`, например `sheepfold-parent-v0.1.57.apk`.
  Нужны `state=uploaded`, положительный размер до 128 МиБ и `digest=sha256:<64 hex>`.
  Детский/OpenWrt APK, suffix `-debug`, версии с ведущими нулями и неполные assets не подходят.
- JSON не более 1 МиБ, до 100 assets на релиз. Connect timeout 5 секунд, read timeout 15 секунд,
  предел чтения JSON 30 секунд, APK 300 секунд. Отмена блокирующего чтения может дождаться
  socket timeout, поэтому мгновенная остановка не обещается.
- Metadata redirect запрещён. APK начинает загрузку только с точного release-пути репозитория
  на `github.com`; до трёх переходов допустимы только по HTTPS на этот путь или
  `release-assets.githubusercontent.com` / `objects.githubusercontent.com`.
  Userinfo, fragment и нестандартный порт запрещены. Системное TLS-доверие не отключается.
- GitHub не получает семейные данные, адрес роутера, его Bearer и логи. Получает обычные
  сетевые метаданные: исходящий IP и общий User-Agent.
- Сверяются размер, SHA-256, package ID `app.sheepfold.android`, имя версии,
  строго больший `versionCode` и тот же набор текущих сертификатов подписантов установленного
  APK. Контрольная сумма GitHub не доказывает авторство: доверие задаёт подпись установленного
  приложения. Законная ротация ключа тоже требует отдельного дизайна, не обхода проверки.

## Хранение и установка

Отмена переводит экран в «Отменяем скачивание…». Новый запуск запрещён до завершения
старого Job и его очистки: `isActive=false` недостаточно, потому что отменённая coroutine
ещё может удалять общий временный файл в `finally`. Защита использует `isCompleted`.

`cacheDir/app-updates/parent.part` используется во время подготовки. После проверки файл
переименовывается в `parent.apk`; рядом атомарно записывается `ready.json` через Android
`AtomicFile`. В JSON только версия, фиксированный URL, размер, SHA-256 и время начатого
запроса разрешения; максимум 4 КиБ, без данных семьи и путей из внешнего ввода.
При восстановлении метаданные проходят `ParentUpdatePolicy.release`, а байты проходят те же
проверки размера, хеша, package/version и сертификата, что перед установкой. Сам JSON не
доказывает доверие к APK. Неизвестная схема, оборванный JSON, чужой URL или потерянный/изменённый
файл не разрешают установку. После успешного обновления старая версия из кеша очищается.

При отмене/ошибке временный `.part` удаляется. Перед новым скачиванием прежний APK и метаданные
заменяются. Один проверенный APK занимает не более 128 МиБ до следующей загрузки, установки
или очистки кеша. Cache не входит в backup; Android вправе очистить его, тогда загрузка нужна
заново. Отказ разрешения или `ActivityNotFoundException` сами по себе файл не повреждают.

Ожидание записывается до запуска Settings и снимается до передачи APK установщику.
Поэтому отмена установки и повторный запуск приложения не создают цикл системных окон.
Прошедшие 30 минут или перевод часов назад прекращают автоматическое продолжение, но не
удаляют проверенный APK. Результат permission Activity не считается доказательством разрешения:
повторно вызывается `canRequestPackageInstalls()`.

Перед установкой файл перепроверяется. Неэкспортированный `ParentUpdateFileProvider` выдаёт
системному установщику временное read-разрешение только на выбранный content URI из
`app-updates/`, не на весь cache/files/external storage. Устанавливает Android после
подтверждения человека. Нет тихой установки, uninstall, сброса данных или смены signing key.

## Подготовка публикации

По отдельному разрешению на выпуск, из корня репозитория:

1. Увеличить `versionCode` и числовой `versionName` в `android/app/build.gradle.kts`.
2. Пройти проверки и собрать release с тем же offline signing key. Настройка ключа:
   [Android и GitHub Actions](github-actions-openwrt-build.ru.md).
3. Проверить package ID, versionCode и сертификат средствами Android SDK. Не публиковать
   локальный debug APK как production-обновление.
4. Прикрепить APK под точным именем к недрафтовому стабильному релизу. Актуальный Android
   APK должен оставаться среди последних 20 релизов. Не заменять байты старого asset.
5. Проверить GitHub `size` и `digest`; если digest отсутствует, исправить публикацию,
   не отключать проверку APK.
6. На отдельном телефоне пройти обновление со старой версии тем же ключом; проверить
   сохранение привязки, темы, языка и защиты.

GitHub Actions artifacts в ZIP, требующие входа, не являются публичными release assets.
Зелёная CI-сборка сама по себе не делает APK доступным этой кнопке.

### Отдельная тестовая публикация

Владелец разрешил 31.08.2026 публикацию `0.1.58` / code `59`, чтобы самостоятельно
проверить кнопку обновления поверх установленного debug APK `0.1.57`.
Для этого пути нужен прежний локальный тестовый сертификат, не новый production-ключ.
Такой APK остаётся debug-сборкой для испытаний и не считается готовым стабильным выпуском.

Файл `sheepfold-parent-v0.1.58.apk` добавлен в уже существующий
`v0.1.0-experimental.1`, без замены прежних assets и без создания нового релиза роутера.
У этого контейнера исторически `draft=false`, `prerelease=false`: установленный updater
не читает prerelease. Название и описание явно помечают тестовый статус; флаг GitHub
не является обещанием production-готовности. Исходный commit APK указывается отдельно:
старый тег экспериментального контейнера не обозначает исходники нового Android APK.

Перед загрузкой сверить сертификат с APK, прочитанным с телефона через `adb pull`,
package ID, возрастающий versionCode и SHA-256. После загрузки сверить `state`, `size`,
`digest`, URL и байты публичного скачивания без GitHub-аутентификации. Роутерные assets,
статус latest и ключи подписи не менять. Установку на телефоне оставлять владельцу;
публикация файла ещё не доказывает успешный переход через системный установщик.

## Проверки

Рабочий каталог: корень репозитория, PowerShell. Нужны JDK 17, Android SDK и прогретые
Gradle dependencies. Локальный кеш настроить по [Android-стенду](android-test-lab.ru.md).

```powershell
.\android\gradlew.bat -p android :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest '-Pkotlin.compiler.execution.strategy=in-process' --offline --no-daemon --max-workers=2 --console=plain
node --test tests/androidParentManagement.test.mjs tests/adminConfigApi.test.mjs
npm.cmd run quality:docs:all
git diff --check
```

Ожидаются `BUILD SUCCESSFUL`, ноль failures, исправные ссылки/теги и пустой diff-check.
`ParentUpdatePolicyTest` проверяет APK, версии, origin и подпись;
`ParentUpdateTransportTest` исполняет скачивание на fake HTTPS с порчей, обрезкой,
превышением размера, redirect и отменой. `ParentDeviceGroupsTest` проверяет принадлежность.
Node-тест исполняет shell-проекцию владельца на fake UCI без живого роутера.

Ожидание завершения cleanup дополнительно защищает source-contract проверка
`cancelledUpdateCannotRestartBeforeSharedFileCleanupCompletes`; отдельный UI-сценарий
проверяет отсутствие кнопок повторной загрузки во время отмены. Эти две проверки не
имитируют задержку реального Android socket.

Для изолированного прогона сначала собрать app/test APK командой Gradle выше.
После первичной настройки Android-стенда из того же PowerShell запустить только проектный
AVD, не весь `emulatorFull`. Пример API 28; для API 35 заменить имя на `SheepfoldLabApi35`
и порт на `5572`. Порт должен быть свободен; не запускать второй экземпляр того же AVD.

```powershell
. .\tools\android-testing\androidLabCommon.ps1
$sdk = Get-AndroidLabTools
Start-Process -FilePath $sdk.Emulator -ArgumentList @('-avd','SheepfoldLabApi28','-port','5570','-no-snapshot','-no-boot-anim','-noaudio','-gpu','swiftshader_indirect','-no-window') -WindowStyle Hidden
Wait-AndroidLabBoot -AdbPath $sdk.Adb -Serial emulator-5570
```

Ожидается загрузка за ограниченные helper-ом 240 секунд. Для уже запущенного проектного
эмулятора второй запуск не нужен. Затем установить APK и выбрать только нужные классы:

```powershell
$adb = Join-Path $env:ANDROID_HOME 'platform-tools\adb.exe'
$serial = 'EMULATOR_SERIAL'
if ($serial -notmatch '^emulator-\d+$') { throw 'Нужен отдельный тестовый эмулятор' }
& $adb -s $serial emu avd name
& $adb -s $serial install -r -t android/app/build/outputs/apk/debug/app-debug.apk
if ($LASTEXITCODE -ne 0) { throw 'Не установлен основной тестовый APK' }
& $adb -s $serial install -r -t android/app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
if ($LASTEXITCODE -ne 0) { throw 'Не установлен APK тестов' }
& $adb -s $serial shell am instrument -w -r -e class app.sheepfold.android.updates.ParentUpdateFlowTest,app.sheepfold.android.ui.main.ParentAppUpdateTest,app.sheepfold.android.ui.main.ParentReadPanelsTest app.sheepfold.android.test/androidx.test.runner.AndroidJUnitRunner
& $adb -s $serial emu kill
```

`EMULATOR_SERIAL` заменить serial тестового эмулятора. Для текущего набора ожидается `OK (27 tests)`,
а не только нулевой exit code. UI-тесты используют вымышленные данные, не обращаются к
GitHub/роутеру и не запускают installer. Они не доказывают production-подпись и установку
обновления на конкретном OEM-телефоне.
`emu avd name` должен показать выбранный `SheepfoldLabApi28`/`SheepfoldLabApi35`, а обе
установки APK вывести `Success`; иначе остановиться, не подставлять serial физического телефона.
Последняя команда останавливает только выбранный эмулятор; после ошибки также остановить
свой запущенный AVD. Его тестовые APK остаются в виртуальном устройстве для повторного запуска.

`ParentUpdateFlowTest` исполняет настоящий ViewModel и AtomicFile в отдельных тестовых
cache-каталогах. HTTPS и платформенная проверка APK заменены синтетическими адаптерами:
никаких скачиваний с GitHub, выдачи разрешений или реальной установки. Набор проверяет
автоматический переход, однократность, отказ/возврат разрешения, восстановление метаданных
в новом ViewModel (модель потери процесса), отмену установщика, повреждение/очистку кеша,
ошибку открытия и истечение 30 минут. Это не доказательство поведения Settings конкретного
производителя; его проверять отдельно на выделенном телефоне, без удаления данных приложения.
После набора удаляются только его временные cache-каталоги, а ViewModelStore очищается;
эмулятор, запущенный для этой проверки, затем штатно останавливается. Подключённый телефон
в этот сценарий не включать. При отсутствии `ready.json` старые сборки не могут восстановить
неизвестные метаданные APK: исправление не обещает восстановить скачивание, сделанное до него.
