# Sheepfold r323: изменение выбранного хранилища во время отправки

Дата: **13.09.2026**. База: **r322, `276d4d042d65ffca880b96d5fc056df0cd583f8f`**,
потомок принятого `bdb3a92`. Работа выполнена локально, в ветке `main`, без push.

## Результат

Исправлены **B130–B131**: выбор backend проверяется на границах обоих облачных
отправителей; Google отличает недоступное чтение выбора от успешного пропуска.
[Накопительный реестр](bug-register.ru.md) содержит **131 карточку**, а не 131
независимо подтверждённую уязвимость. Все прежние карточки сохранены.

Production изменён только в двух экспортёрах и версии Makefile (0.1.0-323).
Новые зависимости, фоновые задачи, форматы сохранённой конфигурации и миграции
не добавлены. Правила интернет-доступа/D01, код Android, workflow и исполняющие
runner-скрипты не изменены. Карта зависимостей уже содержит оба изменённых теста,
поэтому новые категории или искусственное расширение tooling не требуются.

## Что было воспроизведено на полной неизменённой r322

### Выбор RAM не останавливал отправку

После последнего MKCOL Яндекс Диска модель переключает только
`sheepfold.global.log_storage` с `yandex_disk` на `ram`. Реквизиты и корневая папка
остаются прежними. Настоящий скрипт продолжает PUT/HEAD для двух ожидающих архивов
и копии настроек, удаляет оба локальных архива и возвращает
`{"ok":true,"pushed":3,"errors":0}`. Трасса содержит точку изменения, каждый
последующий сетевой вызов, исходные байты и существование архивов в конце.

В Google Drive выбор меняется с `google_drive` на `ram` при ответе поиска папки.
Настоящий sender продолжает последующие поиски, загрузки и metadata-проверки;
ожидающий архив удаляется. Оба пути `push-events` тоже игнорировали такое изменение.
Это проблема выбора backend, а не повтор B92/B129 о смене его реквизитов.

### Технический отказ вместо выбора трактовался как пропуск Google

При существующей опции `google_drive` getter выводит пустую строку либо
`google_drive`, затем завершается ошибкой. Оба отправителя исходной r322 возвращают
exit 0 с пустым stdout и без отправки. Прежний `global_get` приписывал `ram` после
отказа; полученный текст не совпадал с `google_drive`, после чего выполнялся
успешный ранний выход. Неисправность скрывалась под нормальным «отправлять не нужно».

Все HTTP/UCI-данные синтетические. Реальные аккаунты не использовались. Файловые
операции и архивирование настоящие, в изолированном `.build`; изменение настроек
и наличие последующих запросов подтверждены trace, не только grep исходника.

## Почему исправлено именно так

`senderStoragePinned` создаётся самим отправителем, а не принимается из окружения.
Проверка внутри действующих контекстов читает только `global.log_storage`. Если
getter отказал, в том числе после печати правдоподобного значения, продолжать
нельзя. Если getter успешен, значение должно оставаться текущим облаком.

Проверять всю секцию `global` было бы чрезмерно: отдельный контроль доказывает, что
изменение глобальной блокировки интернета не отменяет правильную отправку. Проверка
только один раз слишком ранняя; изменение может произойти во время HTTP. Блокировка
всех редакторов на время сети требует отдельной архитектуры и не введена. Отправка
не перенаправляется автоматически на новое хранилище и не повторяется сама.

Яндекс наследует флаг из уже существующего `yandex_sync_run`; Google получил
небольшой `drive_sender_run`. Внутренние команды **не вызываются в условии `if`/`||`**,
чтобы не изменить обработку ошибок их старых шагов. Google-wrapper различает отказ
get, подтверждённое отсутствие опции и настоящий выбор другого backend. Только
подтверждённое отсутствие сохраняет default RAM; настройки не записываются.

Прямые `list`, `verify`, `download` и диагностический `status` не становятся
автоматическими отправками, поэтому новый флаг в них не включается. Исправление
не запрещает явное скачивание имеющейся облачной копии после выбора RAM для новых
журналов. Остальные пользовательские контракты и шифрование TLS не менялись.

## Существенные ограничения

Проверка замечает доступное чтению изменение на границе. Она не может отозвать
байты уже ушедшего HTTP. Сохранившийся локальный архив не означает отката облачного
объекта. Поздние тесты специально проверяют, что раньше отправленные и удалённые
архивы не возвращаются при смене настройки на последнем шаге.

Остаются окно между проверкой и действием, ABA (значение успело измениться и
вернуться), общий порядок параллельных отправителей и согласованность всех UCI
writers. Измерение нагрузки от дополнительных getter на слабом роутере не выполнено.
Не используется единая блокировка конфигурации и не устанавливаются часы/таймеры.

Начальный Google-отказ теперь даёт `storage_unavailable` и exit 1 до HTTP. Но его
исторический `.gdrive-sync-status.json` не перепроектирован: ранний отказ не
гарантирует новой отметки в нём. Яндекс сохраняет существующий завершающий статус
с прежними ограничениями отказа RAM/часов. Исправление не выдаётся за обработку
абсолютно всех способов запуска, диагностики и повторов.

XML/quota/prune Яндекса, восстановление конфигурации, RAM-квоты и обслуживание
аварийных файлов остаются открытыми. Эта работа не делает backup/restore в целом
подтверждённо готовым продуктом.

## Проверки

Новые **39** сценариев (15 Яндекс, 24 Google) исполняют настоящие команды.
На r322: **33 fail / 6 pass**. На исправлении: **39 pass / 0 fail**, без пропусков.
Исходные файлы сохранены в evidence с SHA-256. Эти числа не обозначают 33 отдельных
уязвимости: сценарии покрывают две группы ошибок и контрольные случаи.

| Область | Результат |
| --- | ---: |
| Яндекс и общие прямые соседи, 13 файлов | 516 pass, без fail/skipped/cancelled |
| Пять затронутых групп Google Drive в одном файле | 112 pass, без fail/skipped/cancelled |
| Один test-IPK файл на двух редакциях | 25 pass на каждой редакции, считаются один раз |
| **Всего уникальных сценариев в 15 файлах** | **653 pass** |
| Новые сценарии (уже включены выше) | 39 pass |
| Синтаксис двух изменённых shell | sh и BusyBox ash — без ошибок |
| Синтаксис двух изменённых JavaScript-файлов | node --check — без ошибок |
| Изменённые Markdown-файлы | 9, проверка пройдена |

**Полный набор тестов не запускался.** Повтор второго IPK и дополнительный прогон
новых сценариев не прибавляются к числу уникальных проверок. Тестовые пакеты
Standard/AI Support собраны; оба исправленных helper совпадают с исходниками и
имеют 0755. Hardening выполнен на двух распакованных rootfs с exit 0, без установки
пакета на хост. История, рабочая копия и Git-экспорт проверяются отдельно при выдаче.

Советник quality-plan рекомендовал широкие категории/full из-за типов изменённых
файлов. Применены критерии владельца и реальная область влияния: шифрование,
Android, firewall и механизм runner не менялись. Большой Google-файл проверен по
пяти явно названным группам; вся Yandex-область и общие прямые потребители пройдены.
Предупреждения размера legacy-файлов/fixture сохранены в `quality-plan.log`;
рефакторинг всего модуля ради порога не добавлялся.


### Уровень доказательств

UCI и HTTP — записывающие модели; Google `jshn` — модель соответствующих функций.
Ни одного реального запроса Google/Яндексу. Shell, файлы, tar/cmp и изолированные
POSIX-блокировки там, где они применимы, настоящие. Успешный syntax-check BusyBox
не называется выполнением всех fault-тестов на BusyBox: для детерминированных
подстановок используется системный sh. Свежих Android/SDK/роутерных проверок нет.

Изменённые шаблоны стендов сохраняют прежние сценарии и лишь умеют менять backend
в заданной точке. Каждый отрицательный случай требует trace вызова/изменения.
Первый технический запуск baseline был прерван внешним лимитом до assertions;
повторные полные новые наборы завершены. Прерванный запуск не включён в числа.
Дополнительные повторения ключевых Google-сценариев записывают stdout/exit в JSON.

## Как повторить

Рабочий каталог — корень репозитория. Среда: Linux/POSIX sh, Node.js 22+, Python 3,
awk/sed, tar/gzip, cmp, обычные файловые утилиты и flock. Облачные ключи и роутер
не нужны. Фиктивные данные создаются в `.build` и удаляются тестом; нет изменений
конфигурации реального роутера. Не запускать production-скрипт вместо fixture.

Новые сценарии выполняются отдельно, чтобы не поднимать несвязанные runtime:

```sh
node --test --test-name-pattern='selected storage boundary' tests/yandexContextRuntime.test.mjs
node --test --test-name-pattern='selected storage boundary' tests/googleDriveUploadRuntime.test.mjs
```

Ожидаются 15 и 24 pass, exit 0, отсутствие fail/skipped/cancelled. Для исследования
старого поведения установить `SHEEPFOLD_YANDEX_TEST_SOURCE` или
`SHEEPFOLD_GDRIVE_TEST_SOURCE` в каталог с соответствующим исходным shell-файлом
r322, не заменяя рабочий production. На старом коде ожидаются отказы assertions.

Профильные соседи Яндекса, диспетчер, writer, упаковка и карта зависимостей:

```sh
node scripts/run-test-category.mjs --file yandexContextRuntime.test.mjs --file yandexDiskRuntime.test.mjs --file yandexBackupRuntime.test.mjs --file yandexUploadRuntime.test.mjs --file yandexEventsRuntime.test.mjs --file yandexSyncRuntime.test.mjs --file yandexDownloadRuntime.test.mjs --file logStorage.test.mjs --file logWriterRuntime.test.mjs --file portableShellAndStatus.test.mjs --file packageHardeningRuntime.test.mjs --file changeImpact.test.mjs --file testCategories.test.mjs
```

В большом Google-файле выбраны новые границы, прежний контекст папок, загрузка,
наблюдение статуса и настроенный журнал; не перезапускаются все несвязанные XML,
экранные и Android-сценарии:

```sh
node --test --test-name-pattern='selected storage boundary|folder context|independent upload evidence|status observation safety|configured journal snapshots' tests/googleDriveUploadRuntime.test.mjs
```

Упаковка и проверка метаданных выполняются без установки на хост:

```sh
python3 scripts/build-test-ipk.py --variant all
SHEEPFOLD_TEST_IPK="$PWD/.build/ipk-output/luci-app-sheepfold-family-internet-control_0.1.0-323_all.ipk" node scripts/run-test-category.mjs --file testIpkPermissions.test.mjs
SHEEPFOLD_TEST_IPK="$PWD/.build/ipk-output/luci-app-sheepfold-ai-support_0.1.0-323_all.ipk" node scripts/run-test-category.mjs --file testIpkPermissions.test.mjs
node scripts/checkDocumentation.mjs --git 276d4d0
git diff --check
```

Ожидаются два test-IPK, по 25 успешных проверок, исправные ссылки Markdown и пустой
`diff --check`. Реальный install/opkg/APK и SDK-compile этим не заменяются.
ESLint требует закреплённых npm-зависимостей. В этом окружении его offline-запуск
возвращает ENOTCACHED; проверка JS-синтаксиса не подменяет lint. Ошибку Python/PATH,
сокетов или отсутствующего toolchain нужно отделять от отказа проверяемого продукта.

## Планы после этого прохода

Нужны подтверждённый XML-reader Яндекса и безопасное решение о квоте/очистке,
исторический sync-status Google, общая политика конкурентных отправителей,
ограничения RAM и отдельная проверка восстановления. Текущая версия — локальный
интеграционный снимок, не утверждение о стабильном выпуске для домашнего роутера.
