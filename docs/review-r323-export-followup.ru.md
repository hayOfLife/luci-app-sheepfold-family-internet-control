Принятая ранее база — `bdb3a92`. Исходный кандидат r323 —

## Результат и важная граница

Устранены B136–B138 в браузерном экспорте: открытые Wi-Fi-реквизиты, выдача файла
больше лимита собственного импортёра и потеря обработки синхронных ошибок.
Оба ранее неуспешных теста квоты согласованы с защитной блокировкой. Детальные
сценарии, причины, альтернативы и ограничения находятся в
[реестре B136–B138](bug-register.ru.md), текущее поведение — в
[контракте экспорта](settings-backup.ru.md).

**Автоматический `archive-push` Google Drive и Яндекс Диска не разблокирован.**
Он по-прежнему возвращает `config_backup_unavailable` для выбранного облака.
Весь архивный проход запрещён, включая пакетную отправку старых журналов;
сырые старые копии не отправляются и не удаляются. `push-events` не изменён
в этой итерации. Контейнер полного экспорта остался `sheepfold-settings-encrypted-v1`;
формат читаемого — `sheepfold-settings-export-v2`. Новый формат и сохранение
пароля шифрования на роутере не вводились.

Проверка существующего экспорта была необходима до его фоновой интеграции:
название «без секретов» не являлось доказательством для `wps_pin`, `r0kh`, `r1kh`.
Новый результат не означает универсального обнаружения секретов в любых новых
или сторонних UCI-полях. Автоматический безопасный экспорт ещё не реализован.

## Что изменено

| Область | Прежнее поведение | Исправление и причина |
| --- | --- | --- |
| B136: Wi-Fi-секреты | WPS PIN и ключи держателей 802.11r попадали в читаемый JSON | Три точных имени добавлены в общий классификатор экспорта, импорта и подстановки текущих секретов. Вся опция маскируется, а не разбирается вторым парсером |
| B137: размер копии | Скачивался файл, превышающий 5 МиБ, который собственный импорт сразу отклонял | Единый предел применяется к конечному UTF-8 JSON; учитываются отступы и Base64 шифрованной оболочки. Лимит импорта не повышен, поля не обрезаются |
| B138: ошибки UI | Синхронная ошибка подготовки снимка обходила Promise-обработчик и оставляла кнопку выключенной | Снимок, encrypt и подготовка файла объединены в одну цепочку с завершающим catch; обычный экспорт имеет try/catch. Ошибки сообщаются, успех не имитируется |
| Два теста квоты | Ожидали `quota_unavailable` или успешный архивный проход, хотя защита останавливает его раньше | Reader квоты проверяется отдельно, затем проверяется явный отказ архивной команды без сети и удаления. Исправлена модель ожидания, защита не ослаблена |

### Семантика Wi-Fi-опций

Названия сверены по первичным источникам: [таблица wireless OpenWrt](https://openwrt.org/docs/guide-user/network/wifi/basic)
описывает `wps_pin` и ключи в списках `r0kh`/`r1kh`; [исходный парсер hostapd](https://w1.fi/hostapd/devel/config_8c_source.html)
показывает чтение ключевого материала этих списков. Это внешняя проверка смысла
опций, не источник сведений о наличии таких настроек у владельца.

Все испытания используют синтетические реквизиты. Доказано наличие данных в
выдаваемом JSON прежнего кода, не факт чужого доступа к реальному Wi-Fi.
Старые файлы экспорта исправление не удаляет и не маскирует задним числом.

## Проверки и границы доказательства

Выполнено **147 уникальных тестов в 11 файлах**, все выбранные сценарии прошли.
Основной штатный runner выполнил 128 сценариев в 10 файлах. Отдельно выполнены
19 сценариев группы квоты Яндекс Диска. Полный файл Yandex context не назван
пройденным: его остальные старые archive-сценарии не относятся к разрешённому
сейчас поведению и не запускались в этом проходе.

**Сравнение до правки.** Те же 18 выбранных синхронных/секретных сценариев запущены
на настоящих `backup.js` и `backup-panel.js` из предыдущего review-кандидата:
17 не проходят, один контрольный проходит. Это не 17 независимых дефектов.
Три новых группы названы по причинам, а не по количеству assertions.
В дополнительном первоначальном прогоне были 18 отказов из 21; он сохранён
отдельно и не смешан с окончательным набором, в который добавлены сценарии UI.

**Что реально выполняется.** Настоящий код LuCI загружается в Node VM. WebCrypto,
JSON/UTF-8 кодирование и чтение файлов настоящие. DOM, скачивание браузера и UCI
представлены записывающими моделями. Кнопка вызывает настоящий обработчик панели,
а проверки анализируют текст, переданный в `downloads.textFile`. Тесты восстановления
сверяют реальные вызовы адаптера с синтетическим UCI-снимком. Это не запуск браузера
LuCI, не установка на роутер и не подтверждение работы Wi-Fi.

**Остальной старый cloud suite не объявлен зелёным.** После намеренной блокировки
archive-push остаются старые ожидания успешной архивной отправки в нескольких
файлах. Они не удалены и не заменены пустыми assertions. Их следует разделить
на тесты текущего запрета, разрешённого journal-пути и будущего безопасного
экспортёра. Полный suite не запускался, Windows/Git Bash не запускался.

Дополнительно проверены 14 JavaScript-файлов и два shell-файла. LuCI-модули
проверялись внутри функции, как при их загрузке LuCI; прямой `node --check`
в ESM-режиме отвергает их верхнеуровневый `return`. Первоначальный отказ такого
неподходящего запуска сохранён в `syntax-initial.json`; исправлена команда
проверки, не исходник ради синтаксического обхода. Документационный анализатор
проверил 291 Markdown-файл. Перегенерация RU и zh_Hans сохранила все прежние
значения и добавила по одной новой строке сообщения.

Повтор в независимом клоне после применения совокупного patch:
24 новых export-сценария и 8 проверок запрета сырой копии — **32 из 32**.
Этот повтор не прибавлен к числу 147. Пакет не публиковался и не устанавливался.

ESLint недоступен: загрузка `eslint` вернула `ERR_MODULE_NOT_FOUND`. Зависимости
не устанавливались. Проверка синтаксиса не заменяет линтер. Новые IPK/APK,
OpenWrt SDK, Android и аппаратные тесты в этом проходе не выполнялись.

## Команды повторения

Рабочий каталог — корень отдельной копии кандидата. Нужны Node.js с WebCrypto,
Python 3, sh/bash, tar и flock для соответствующих Linux-проверок. На Windows
использовать существующее окружение проекта; настоящий Windows-прогон не
подтверждён и не заменяется unit-проверками параметра platform.

```sh
node scripts/run-test-category.mjs --file backupExportSafety.test.mjs --file settingsBackup.test.mjs --file backupRecoveryRegression.test.mjs --file luciPersistenceAdapters.test.mjs --file frontendModules.test.mjs --file overviewLocalization.test.mjs --file testCategories.test.mjs --file changeImpact.test.mjs --file runtimeProcess.test.mjs --file cloudArchiveSafety.test.mjs
node --test --test-name-pattern='Yandex quota setting boundary' tests/yandexContextRuntime.test.mjs
node scripts/checkDocumentation.mjs --all
git diff --check
```

Ожидается exit 0 у каждой команды. Ни одна из них не выполняет commit/push,
установку, реальный облачный запрос или изменение конфигурации роутера.
Временные данные тестов находятся в `.build` и удаляются соответствующим fixture.
Если Linux не содержит flock, нужно исправить среду, а не отключать блокировку
производственного кода. Инфраструктурный timeout не является результатом программы.

## План безопасной фоновой интеграции — ещё не реализован

1. Зафиксировать общую проверяемую схему экспортируемых секций/опций и их
   секретности для LuCI и роутерного исполнителя. Проверить реальные ключи
   установленных редакций и Wi-Fi, исключаемые pairing/identity-данные и
   неизвестные расширения. Не переносить текущий regexp как доказанную универсальную
   защиту и не создавать второй, несогласованный формат.
2. Реализовать читаемое представление того же `sheepfold-settings-export-v2`:
   Sheepfold, постоянные DHCP-host и допустимые wireless-типы, без секретов.
   Использовать согласованный снимок UCI и лимиты до облачного действия.
3. Передавать загрузчику только подготовленный и проверенный безопасный payload;
   старую очередь произвольных tar не считать автоматически допустимым источником.
   Проверять фактические байты обоих экспортёров и отсутствие всех контрольных
   секретов, а не только отдельный helper.
4. Выполнить round-trip через существующий importer: тот же/другой роутер,
   сохранение совпадающих секретов, отсутствие изобретённых секретов, отказ до
   UCI staging и корректные службы. Зашифрованный режим требует согласованного
   явного разрешения и пароля, который не сохраняется рядом с копией.
5. Только затем менять разрешение archive-push, обновлять старые ожидания
   успешной отправки и подтверждать native OpenWrt/облака. Общий выпуск, принятие
   кандидата, commit/push и установка остаются отдельными действиями владельца.

## Поставка

Кумулятивный patch применяется к чистому `1e9c43b`, **вместо** предыдущего patch.
Delta patch применяется только после `sheepfold-r323-review-fixes.patch`.
Не применять оба patch последовательно. ZIP содержит полный совокупный кандидат
без `.git`, `.build`, зависимостей и журналов. Новый bundle не создаётся: без
нового коммита он не переносит незакоммиченные файлы.

```sh
git clone --branch main sheepfold-r323-main.bundle sheepfold-review-followup
cd sheepfold-review-followup
git rev-parse HEAD
# Требуется 1e9c43bfea54aba15d7020fbdbe84ad5dc23b7c0
git switch -c review/r323-export-followup
git apply --check ../sheepfold-r323-review-followup.patch
git apply ../sheepfold-r323-review-followup.patch
```

суммы поставляются отдельным протоколом в архиве доказательств.
