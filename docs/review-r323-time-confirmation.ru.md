## B157: успех означал только три совпавших поля

Прежний обработчик после двух commit сравнивал только zonename, timezone и
router_time_configured. Не сверял список NTP, оба переключателя, типы секций,
зеркала настроек и время записи. Кроме того, `|| true` позволял принять ожидаемую
строку от неуспешно завершившегося `get`.

В модели UCI раздельно хранятся частная очередь и два настоящих файла. Commit
меняет именно те файлы, которые создаваемые helper снимки затем восстанавливают.
Это лучше простой записи вызова, но **не полноценная libuci**.

Самый показательный сценарий: существующий список содержит два старых сервера.
Подставленная UCI-команда `delete system.ntp.server` отказывает и оставляет запись.
Рабочий helper подавляет этот отказ, добавляет новые адреса и делает commit.

| Наблюдение | Предыдущий кандидат | Исправленный кандидат |
| --- | --- | --- |
| Прочитанный после commit список | Старые и новые серверы вместе | Расхождение обнаружено |
| Итоговый список в файле модели | Четыре адреса | Прежние два адреса после восстановления |
| Ответ | `status=ok`, указаны только новые серверы | Exit 4, `time_save_failed`, `config_files_restored=1` |
| Перезапуск NTP | Выполнен | Не выполняется |

Отдельно неуспешный `get` печатает точный ожидаемый zonename и exit 1.
Прежний helper возвращает успех; исправленный отвергает результат и проходит
существующий путь восстановления. След отказавшей команды обязателен в тесте.

Теперь `verify_saved_time` подтверждает 16 значений: три типа секций;
zonename/timezone; enabled/enable_server; весь упорядоченный список NTP;
восемь соответствующих настроек/маркеров Sheepfold, включая timestamp.
`saved_value_equals` сначала проверяет код завершения `command uci -q get`, затем
значение. Ошибка или отсутствие любого из них не позволяет отключить rollback
и перейти к restart.

**Почему так:** проверка только одного дополнительного поля оставила бы остальные
пути ложного успеха. Сверка всей конфигурации чрезмерна: независимая опция не
отменяет правильную запись времени. Тест изменения такой опции проходит без
отката. Ни новый парсер UCI, ни общий `uci revert` не добавлены. Наличие самой
проверки не исправляет причины всех возможных отказов UCI.

**Существенные границы:** чтение последовательное и относится к эффективным UCI-
значениям. Оно может видеть общие deltas, не является атомарным снимком постоянных
файлов, не блокирует сторонние writers. Сохранён предыдущий файловый rollback:
после начала commit он может затронуть параллельную запись другого процесса.
Не заявляется, что один lock или полный список проверок решил R03. При неудачном
восстановлении остаётся exit 6 и сохраняются аварийные снимки. Успешная запись с
отказом NTP по-прежнему даёт exit 5 с `persisted=1`, `runtime_applied=0`.

## B158: значение «оставить текущее» устаревало ещё до lock

Пустой CLI-аргумент означает наследование текущего значения. Прежний `save_time`
выполнял чтения раньше `sheepfold_lock_acquire`. Пока он ожидал, другой владелец
lock мог сохранить новый часовой пояс и серверы. Первый скрипт продолжал с прежними
значениями, хотя его аварийный снимок уже относился к более новому состоянию.

Независимый Linux-процесс держит настоящий flock. Второй процесс достигает попытки
захвата (подтверждено барьером), но ещё не имеет права писать. Под lock файлы меняются
с UTC/старых серверов/ru на Asia/Shanghai/current.example.test/cn. После освобождения:

| Сохранено вторым процессом | Прежний кандидат | Исправленный кандидат |
| --- | --- | --- |
| Часовой пояс | `UTC`, `UTC0` | `Asia/Shanghai`, `CST-8` |
| Серверы | Прежние два адреса | `current.example.test` |
| Страна в отметке настройки | `ru` | `cn` |
| Exit | 0 | 0 |

Теперь захват lock и установка cleanup предшествуют разрешению наследуемых значений.
Явно переданные аргументы по-прежнему сохраняются как намерение пользователя;
второй контрольный сценарий это проверяет. Лимит ожидания 10 секунд не увеличен.

**Почему так:** очередное чтение до lock не устраняет причину. Перенос выбора внутрь
существующей сериализации устраняет именно воспроизведённую гонку без новых
глобальных блокировок. Это отдельный shell-путь, не прежний фикс очереди импорта LuCI.

**Ограничения:** только процессы, использующие этот же lock, следуют данному порядку.
Первичный `uci_get` продолжает скрывать отдельные ошибки, а проверка status в этом
проходе не изменена. Нет автоматической защиты всех CLI/ботов/CGI, свежего сетевого
снимка LuCI или доказанной атомарности всей последовательности system/sheepfold.

## B159: отказ date скрывался успешным set

Раньше `date +%s` находился внутри аргумента успешной команды UCI. Отказ внутренней
команды не делал внешний `set` неуспешным. Пустой либо неправильный timestamp
сохранялся, затем конфиги подтверждались и NTP перезапускался.

Проверены пустой и правдоподобный вывод с exit 1, а также пустой и некорректный вывод
с exit 0. В прежнем коде все эти сценарии продолжали сохранение. Теперь число и
статус date проверяются до первого set/add/delete/commit. Результат отказа:

```text
status=error
error=time_clock_unavailable
```

Код завершения 4. Новые настройки не записываются, NTP не перезапускается; временные
снимки убираются существующим проверяемым cleanup. Если убрать их невозможно,
предупреждение не выдаётся за изменённую конфигурацию. При успехе та же отметка
сравнивается в завершающем readback.

LuCI распознаёт только точный exit 4 + status=error + time_clock_unavailable.
Сообщение: «Не удалось прочитать часы роутера. Настройки времени не изменены.
Проверьте роутер перед повторной попыткой». `persisted=true` не устанавливается.
Другие коды и неполный ответ не принимаются за этот контракт. RU JSON получен
штатной генерацией из PO.

**Почему так:** нельзя подставлять текущие часы компьютера агента, придуманный
срок или старую отметку. Ноль при успешном числовом ответе оставлен допустимым как
служебная метка, иначе стало бы невозможно настраивать NTP при ещё неверных часах.
Это не доказательство правильного времени и не новая проверка NTP-синхронизации.
Последующие скачки часов не исключены.

### Проверка внешнего контракта

Сверены первичные исходники [UCI CLI](https://lxr.openwrt.org/source/uci/cli.c) и
[delta-путей](https://lxr.openwrt.org/source/uci/delta.c), просмотр 15.09.2026:
чтение секции возвращает её тип, список выводится через разделитель, `-p` и `-t`
имеют разные задачи. Поэтому здесь не говорится, что обычный get читает исключительно
flash или что частный savedir изолирует все остальные writers. Просмотр исходников
не является запуском native libuci и не фиксирует версию UCI конкретного роутера.

## Дополнительная верификация кандидата

Синтаксис helper проверен через `sh -n` и `busybox ash -n`, четыре Node-модуля —
через `node --check`, time.js — в допустимой для LuCI функциональной обёртке.
RU-JSON побайтово совпадает со штатной генерацией из PO. Проверка всех
**298 Markdown-файлов** и `git diff --check` прошла. Offline ESLint завершился
`ENOTCACHED` и не засчитан как выполненный линтер. Новые пакеты не собирались.

Два способа применения проверены независимыми клонами исходного bundle r323:
совокупный патч и прежний recovery-патч плюс новая delta. **1084 файла** совпадают
с ZIP по байтам и исполняемым режимам. HEAD каждого клона остался `1e9c43b`.
Повтор нового файла и облачной защитной блокировки в восстановленном кандидате:
**43 теста**, к количеству уникальных 235 не прибавляются. Manifest, протоколы
применения, старые helper/time.js и JSON-трассы включены в отдельный checks-архив.

## Как повторить профильную проверку

Рабочий каталог — корень отдельной копии кандидата. Нужны Node.js, POSIX sh либо
Git Bash, Python 3 со стандартной библиотекой, обычные файловые утилиты, а в Linux —
настоящий flock. В Windows native-блокировки остаются явно пропущенными сценариями.
Команды не требуют доступа к облаку и не выполняются на рабочем роутере.

```sh
node scripts/run-test-category.mjs --file timeSaveConfirmation.test.mjs --file timeTransactionRecovery.test.mjs --file timeSettingsLifecycle.test.mjs --file timeAndDetectionSetup.test.mjs --file settingsSaveLifecycle.test.mjs --file luciCommandActions.test.mjs --file portableShellAndStatus.test.mjs --file overviewSettingsExtraction.test.mjs --file overviewFinalRuntime.test.mjs --file frontendModules.test.mjs --file overviewLocalization.test.mjs --file cloudArchiveSafety.test.mjs --file changeImpact.test.mjs --file testCategories.test.mjs --file runtimeProcess.test.mjs
```

Ожидается exit 0 и 235 уникальных успехов в проверенной Linux-среде. Стенд создаёт
синтетические данные внутри `.build` и убирает свои каталоги после сценариев.
Прерванный извне процесс может оставить тестовые данные; это не пользовательские
конфиги. `ETIMEDOUT` означает инфраструктурный отказ, а не доказанный ответ программы.
Не запускайте `sheepfold-time-control save` на основном роутере ради воспроизведения.

## Применение кандидата

Совокупный `sheepfold-r323-review-time-confirmation.patch` предназначен для
чистой копии `1e9c43b`. Дополнительный
`sheepfold-r323-review-time-confirmation-delta.patch` — только для копии с уже
применённым `sheepfold-r323-review-time-recovery.patch`. **Это альтернативы,
не последовательные шаги.** К принятому `bdb3a92` напрямую не применять.

В чистом отдельном клоне r323 сначала проверьте отсутствие собственных изменений
и соответствие HEAD, затем проверьте выбранный патч:

```sh
git status --short
git rev-parse HEAD
git apply --check /path/to/sheepfold-r323-review-time-confirmation.patch
git apply /path/to/sheepfold-r323-review-time-confirmation.patch
```

`/path/to/` заменяется каталогом полученного файла. Пустой status и HEAD `1e9c43b…`
нужны для совокупного способа; поверх предыдущего кандидата используется только
соответствующая delta. Команды не делают commit/push. Не выполняйте reset или
принудительный откат чужой рабочей копии для обхода ошибки применения.

## Оставшиеся риски

Полная согласованность UCI, fallbacks первоначального чтения и status, общая pending-
очередь, права/квоты аварийных копий и runtime после частичного восстановления остаются
открытыми. Проверка теперь делает больше вызовов UCI на ручное сохранение; нагрузка
на физическом маломощном роутере не измерялась. Сохранение файлов не гарантирует
переход часов или применение всех расписаний. Безопасный автоматический экспорт и
облачное восстановление не включены. Кандидат не объявляется стабильным релизом.
