# Sheepfold r316: кодирование путей Яндекс Диска и отказ до MKCOL

Дата: **12 сентября 2026 года**. База: **`da347f1` (r315)**, потомок принятого
`bdb3a92`. Результат — локальная ветка `main`, пакет `0.1.0-316`; в GitHub ничего
не отправлялось. Это интеграционный снимок, не подтверждённый stable-релиз.

## Итог и границы

Исправлены две группы дефектов, **B112–B113**, в общем построении WebDAV URL,
нормализации выбранного корня и ранней проверке пути. Накопительный
[реестр ошибок](bug-register.ru.md) содержит **113 карточек** с причинами решений.

Правила доступа устройств, Android, Google Drive, workflow и runners не менялись.
Решение D01 «Без ограничений» выше чёрного списка устройств для обычного интернета,
отдельные запреты управления и карантин сохранены. Производственная правка не
снимает известные ранние отказы `list`, `verify`, `download`, `push-events` и
`restore-config`: включать их по одному без безопасного полного пути нельзя.

## B112: правильное имя папки становилось неправильным URL

В r315 builder просто соединял HTTPS-base и строку логического пути. Это сохраняло
аргумент shell, но не значение назначения. Символ `#` начинал fragment, `?` — query,
а `%2F` был уже закодированным слешем. Пробел приводил к отказу curl.

Для доказательства кроме модели argv выполнен настоящий curl 8.10.1 против
локального HTTPS-сервера. Использован функциональный префикс исходного скрипта,
с заменой только WebDAV base на `https://127.0.0.1:<port>`; UCI возвращал
синтетические реквизиты. TLS-проверка включена: на время теста создаётся сертификат
с SAN 127.0.0.1 и отдельный доверенный CA, не используется `-k`. Ключ и сертификат
удаляются вместе с временным каталогом. Сервер фиксирует request-target, не
создаёт настоящих облачных папок. Прокси отключён только в изолированном стенде.

| Логическое назначение | Фактические MKCOL в r315 | Фактические MKCOL в r316 |
| --- | --- | --- |
| `/family#2026/logs` | `/family`, `/family` | `/family%232026`, `/family%232026/logs` |
| `/family?view=1/logs` | query вместо части имени | `%3Fview%3D1` внутри пути |
| `/a b/logs` | curl отказывает до запроса | `/a%20b`, `/a%20b/logs` |
| `/literal%2F/logs` | `%2F` передаётся как encoded slash | буквальный `%2F` передаётся как `%252F` |

Кириллица и обычные ASCII-пути проходили также на r315: это контрольные случаи,
не новые обнаруженные дефекты. В частности, curl самостоятельно кодировал часть
не-ASCII, но это не исправляло fragment, query и пробелы.

Новый `webdav_url` принимает логический путь. Разделительные `/` и unreserved
ASCII сохраняются; прочие исходные байты кодируются в `%HH`. Обработка в `LC_ALL=C`
сохраняет UTF-8 без зависимости от locale. Проверяется завершение awk до возврата
URL. Subshell изолирует переменные builder от caller. Новой runtime-зависимости
нет: Python/Node используются в тестах, не на роутере.

Не выбраны ручные подстановки отдельных знаков, декодирование настроек `%XX` и
кодирование всего URL вместе со схемой. Причины и альтернативы — в B112 реестра.

### Совместимость старого href

Сырой URI `href` из WebDAV XML не равен логическому имени. Старый prune не имеет
надёжного decoder, поэтому URI с `%` не передаётся новому builder для DELETE:
иначе двойное кодирование могло бы выбрать другой файл с буквальным процентом.
Тест принудительно достигает этой ветви через модель usage и синтетический href.
Он доказывает отсутствие DELETE, **не исправность XML, квоты или полного prune**.

Полная миграция старых облачных имён, разбор href, свойства namespace/propstat и
проверка копии остаются R15. Старые папки не удаляются и не переименовываются.

## B113: проверка всего пути до первого изменяющего запроса

Настоящий curl из r315 для `/family/../outside` отправлял MKCOL к `/family`, `/`
и `/outside`. Для `/family/./logs` — к `/family`, `/family/` и `/family/logs`.
Подтверждены именно фактические запросы. Полномочия в облаке не расширяются;
анонимный доступ или передача данных в чужой аккаунт не заявляются.

r316 отклоняет отдельные компоненты `.`/`..` и управляющие байты **до первого
MKCOL**. Проверять очередную часть во время обхода поздно — предки уже могли
измениться. Автоматически сворачивать `..` означало бы выбрать другое назначение;
`--path-as-is` также не гарантирует интерпретацию на сервере.

Вызовы metadata/PUT получают URL через отдельное проверяемое присваивание.
Неуспешный encoder с частичным stdout не передаёт пустую или неполную строку
сетевому helper. Полный `archive-push` с недопустимым корнем после транспортной
пробы возвращает `root_unavailable`; нет MKCOL/PUT, локальные архив и журнал
сохранены, staging не создан, UCI saved/pending не меняется. Status даёт ошибку,
а не сведения о подменённом назначении.

Пустой непосредственный аргумент builder недопустим; прежний default root при
подтверждённом отсутствии настройки сохранён. Обычные `.family` и `v1..2`
допустимы в builder/подготовке папок; старый более строгий file-prefix gate
не ослаблен. Отдельная проверка trailing LF относится к прямому аргументу helper:
UCI command substitution всё ещё может отбрасывать завершающие LF.

CI, runner, политика доступа не менялись. По указанию владельца выбраны эти шесть

(562 строки против ориентира 500); ради одной метрики общий fixture не переносился.

На r315 тот же итоговый test-файл даёт **81 pass / 45 fail**. Из 47 новых два
контрольных проходят. **Четыре отказа — отсутствие нового encoder injection:**
старый код не содержит соответствующего awk, поэтому внесённый отказ не достигнут.
Это проверки нового механизма, не доказательство прежней обработки ошибки awk.
Остальные неуспешные assertions тоже не равны числу отдельных уязвимостей.
В native HTTPS сценариях r315 два контроля проходят, шесть нарушают ожидаемый
контракт; этот результат не зависит от новой injection-точки.

Первый новый прогон: 120 pass / 1 fail. Ошибка оказалась в проверочном `printf`:
формат добавлял пустую строку перед каждым аргументом, тогда как тест ожидал одну
перед всей группой. Исправлен формат в тесте, не production и не набор ожидаемых
значений. После дополнительных пяти сценариев итоговый файл содержит 126 pass.
Промежуточные журналы сохранены. Попытка использовать интерактивную сессию
контейнера была недоступна до запуска команды; тесты выполнены обычными exec.

## Безопасное повторение

Рабочий каталог — корень восстановленного репозитория. Нужны Node.js 22,
Python 3 и POSIX sh. На Windows используются проектные пути Git Bash; native
HTTPS-стенд отдельно требует доступных curl и openssl. Не запускать production
команды на основном компьютере напрямую: другие ветви скрипта пишут config,
удаляют архивы и могут обращаться к реальному облаку.

```sh
node scripts/run-test-category.mjs --file yandexDiskRuntime.test.mjs
node scripts/run-test-category.mjs --file logStorage.test.mjs --file logWriterRuntime.test.mjs --file portableShellAndStatus.test.mjs --file packageHardeningRuntime.test.mjs
python3 scripts/build-test-ipk.py --variant all
SHEEPFOLD_TEST_IPK="$PWD/.build/ipk-output/luci-app-sheepfold-family-internet-control_0.1.0-316_all.ipk" node scripts/run-test-category.mjs --file testIpkPermissions.test.mjs
SHEEPFOLD_TEST_IPK="$PWD/.build/ipk-output/luci-app-sheepfold-ai-support_0.1.0-316_all.ipk" node scripts/run-test-category.mjs --file testIpkPermissions.test.mjs
```

Ожидается exit 0. Runtime-fixture работает в `.build/yandex-fixtures`, не использует
личные файлы, настоящие реквизиты или внешнюю сеть. Для сохранения состояния задать
абсолютный `SHEEPFOLD_YANDEX_EVIDENCE_DIR`. Для baseline скопировать исходный helper:

```sh
mkdir -p .build/baseline-r315
git show da347f1:package/luci-app-sheepfold-family-internet-control/root/usr/libexec/sheepfold/sheepfold-yandex-disk > .build/baseline-r315/sheepfold-yandex-disk
SHEEPFOLD_YANDEX_TEST_SOURCE="$PWD/.build/baseline-r315" node --test tests/yandexDiskRuntime.test.mjs
```

Ожидается exit 1 с описанными 81/45; отсутствие интерпретатора или тайм-аут не
доказывает ошибку продукта. Два исторических preflight-сценария r315 по-прежнему
снимают только ранний typo `push-events` **в тестовой копии обеих версий**; новые
сценарии r316 не требуют этой поправки. Это не готовый production push-events.

Архив доказательств содержит `check_yandex_uri_wire.py`. После его распаковки
указать путь в следующей команде вместо `EVIDENCE_DIR` (это каталог доказательств):

```sh
python3 EVIDENCE_DIR/check_yandex_uri_wire.py --check --source package/luci-app-sheepfold-family-internet-control/root/usr/libexec/sheepfold/sheepfold-yandex-disk --output .build/yandex-wire-fixed.json
```

Ожидается exit 0, `allPassed:true` и восемь результатов в JSON. Стенд слушает только
loopback HTTPS, удаляет временный закрытый ключ при штатном завершении; старый
helper можно проверить тем же скриптом без `--check` для записи baseline-трассы.
Доказательства не содержат приватных облачных реквизитов или TLS-ключей.

## Упаковка и проверка поставки

Версия повышена только через `PKG_RELEASE`. Оба IPK собраны штатным Python builder
из Makefile. Это тестовая упаковка, не каноническая SDK-сборка и не установка.
Проверки распакованных пакетов и соответствия helper исходникам сохранены в
архиве вместе с логами, текущим патчем и накопительным патчем от `bdb3a92`.

Итоговая поставка содержит bundle с полной `main`, ZIP через `git archive`, реестр,
этот отчёт и архив доказательств. Git bundle восстанавливается в отдельный клон;
ветка/дерево и файлы ZIP сверяются. Контрольные суммы публикуются отдельным файлом.
Короткий commit поставки приводится во внешней копии отчёта, чтобы не создавать
самоссылку в его содержимом до вычисления Git hash.

## Внешняя сверка и оставшиеся риски

- [curl URL syntax](https://curl.se/docs/url-syntax.html): пробелы требуют кодирования;
  query/fragment отличаются от path; dot-segments нормализуются по умолчанию.
- [RFC 3986 §2.1–2.4](https://www.rfc-editor.org/rfc/rfc3986.html#section-2.4):
  логические данные кодируются при составлении URI, не при случайном повторном разборе.

Эти источники не подтверждают работу аккаунта Яндекс Диска. Ни native UCI/libubox,
ни физический роутер, поведение при потере питания, полный backup/restore или
новые Android/SDK-сборки не проверены. Shell syntax через BusyBox не заменяет
runtime на целевой прошивке. ESLint требует отсутствующих локальных зависимостей;
проверка синтаксиса JavaScript не выдаётся за Lint.

R15 остаётся открытой: namespace-aware XML/propstat, проверка collection при 405,
полные read/write/restore-команды, href decoder, квоты, snapshots и конкурентные
отправители, смена реквизитов и расход RAM. Настройки URI со старыми `%XX` могут
требовать ручной проверки смысла: старый код трактовал их как часть URL, новый
сохраняет буквальное имя. Никакой миграции или удаления старых объектов нет.
