# Аудит r321: сохранность скачанной копии Яндекс Диска

Дата: **13 сентября 2026 года**. База: **r320, `2912fb2`**, потомок принятой
`bdb3a92`. Версия роутерных пакетов: **0.1.0-321**. Изменения локальные: GitHub,
физический роутер и телефон в этом проходе не изменялись.

## Результат

Исправлены B125–B127; накопительный [реестр](bug-register.ru.md) содержит **127 карточек**.
Область — самостоятельная команда `download` в `sheepfold-yandex-disk` и её
диспетчер. Получатель проверяется до записи, новая копия готовится отдельно и
публикуется после успешной последовательности HEAD → GET → HEAD. Основной результат:
неуспешная попытка скачать новую копию не уничтожает старую в проверенных сценариях.

Общие функции HEAD, URL-кодирования, проверки размера, сравнения UCI и экранирования
строк не переписывались. Новый потребитель добавлен в карту тестов. Код Android,
политика доступа, workflow и исполняющие runner-скрипты не изменены. Решение D01
сохранено: «Без ограничений» выше чёрного списка устройств для обычного интернета;
запрет управления роутером и карантин независимы.

Это **локально проверенный интеграционный снимок**, не подтверждённый стабильный
релиз. Отдельные команды `list`/`restore-config`, XML/quota/prune не исправлялись.
Восстановление конфигурации не запускается и не объявляется безопасным.

## Доказательства старого поведения

### B125: ранний отказ

Неизменённая r320 на обычном вызове возвращает exit 127, пустой stdout и сообщение
`remote_path: not found`. Сетевых запросов нет. Причина — строка `remote_path code`
без объявления. Неполные аргументы также обрываются до пользовательской проверки
из-за `$1`/`$2` в диспетчере при `set -u`.

Поздние проблемы исследованы **отдельно**: промежуточный файл отличается от исходника
одной строкой `local remote_path code`. Оригинал, промежуточный файл, их SHA-256 и
точный diff включены в архив доказательств. Нельзя приписывать удаление файлов
неизменённой версии, которая остановилась раньше.

### B126: потеря старой копии

На промежуточном файле GET HTTP 500 удаляет ранее существовавший локальный файл.
При обрыве передачи происходит такая же потеря, а stdout curl может склеиться с
запасным `000`, образуя несуществующий код `200000`. Ссылки и путь с `..` перенаправляют
запись. Используются только синтетические файлы внутри fixture.

Эти результаты подтверждены не только моделью HTTP. Отдельный Python-стенд запускает
настоящий curl и loopback HTTPS-сервер; сертификат проверяется через временную CA.
На варианте только с исправленным объявлением HTTP 500 и обрыв уничтожают прежнюю
копию. Сервер не получает настоящих реквизитов, а произвольные внешние адреса
не используются.

### B127: неполные байты как успех

Пять байтов `short` вместо ожидаемых 26 в прежнем алгоритме дают `ok:true, bytes:5`
и становятся новым содержимым получателя. При корректной передаче HTTP это не
сетевая ошибка: downloader просто не сравнивает ответ с метаданными объекта.
Факт подтверждён и моделью, и настоящим curl через локальный HTTPS.

В r321 размер заранее читается существующим HEAD-reader, фактические байты
проверяются после GET, затем HEAD повторяется. Перед подтверждением сверяются
настройки. Полные обычные, пустые и бинарные файлы принимаются; неподтверждённая
копия не публикуется. В реестре подробно разобраны альтернативы и границы.

## Изменённый контракт

CLI сохраняет форму `download <remote> <local>`. Разрешены имя копии в `backups`,
`logs/...`, `backups/...` и допустимый абсолютный путь внутри этих папок. Локальный
путь остаётся в `/tmp`; проверяется каждый компонент, обычный файл или новое имя.
Ссылки, FIFO/каталог по имени файла, `.`/`..` и пустые компоненты не допускаются.

Прежний файл не открывается curl. Создаётся уникальный соседний каталог 0700,
содержимое 0600, затем выполняется одна публикация `mv -T`. До публикации проверены
метаданные, количество байтов, текущие настройки и JSON-поля результата. Отказ
установки прав или записи не маскируется последующим успешным printf.

| Результат | Ответ |
| --- | --- |
| Скачивание подтверждено и опубликовано | `ok:true`, `remote`, `local`, числовое `bytes` |
| Неполные/лишние аргументы | `usage`, exit 1 |
| Недопустимый облачный/локальный путь | `path_not_allowed` / `local_path_not_allowed` |
| Отказ HTTP/передачи | `download_failed`; при техническом отказе числовой `http:0` |
| Размер не подтверждён | `download_metadata_failed` |
| GET имеет другую длину | `download_size_mismatch` |
| Конечные метаданные изменились | `download_remote_changed` |
| Подготовка или публикация локального файла отказала | `download_local_failed` |
| Замечено изменение контекста | `settings_changed` либо отказ соответствующего HEAD-этапа |

Предварительный отказ настройки может сообщаться через отказ разрешения пути или
метаданных; единая классификация всех отказов UCI этим проходом не завершена.
Сетевые ответы и секреты не вставляются в текст ошибки. Повтор с другим аккаунтом
и откат чужих настроек не добавлены.

### Промежуточные отказы не скрыты

Первый новый прогон: 45/53 прошли, восемь отказов. Семь обнаружили ошибку новой
сериализации: использован существующий encoder содержимого без внешних кавычек.
Кавычки исправлены в production до поставки. Восьмой отказ относился к стенду:
`path` нормализовал `//` до проверки. Теперь traversal и двойной разделитель
передаются в shell буквально. Для wc-fault прочитанный stdin передаётся исправной
реальной утилите, если отказ к этому вызову не относится.

Повтор дал 53/53; затем добавлена проверка отказа encoder с trace, получено 54
уникальных успешных сценария. Финальный повтор из bundle проверяет весь этот файл.
Первый общий запуск соседей прерван внешним лимитом после шести успешно завершённых
файлов, при начале `yandexSyncRuntime`. Два оставшихся файла повторены штатным
runner и прошли полностью. Прерванный файл не считается успешным; журнал сохранён.

### Выбор области

Проверены изменённый CLI, непосредственно используемые URL/HEAD/quote readers,
обёртка хранения и packaging. `yandexBackupRuntime`/`yandexEventsRuntime`, Android,
firewall и writer не запускаются повторно только потому, что находятся в том же
проекте: их функции и используемые ими общие helpers не изменены.

Советник из-за Makefile/документации/карты предлагает широкие категории. Применено
подтверждённое владельцем ограничение на реальные зависимости. Сам advisor/runner
не переписывался. Структурное предупреждение о размере legacy helper сохранено;
перенос всего файла ради порога увеличил бы область изменения.

Синтаксис изменённого shell проверен через sh и BusyBox ash; это не выдаётся за
исполнение всех fault-сценариев встроенными applet BusyBox. JavaScript проверен
через `node --check`. Offline ESLint остановился с `ENOTCACHED`; синтаксис не
заменяет lint. Оба IPK собраны существующим тестовым builder, проверены архивы,
версия, права и совпадение helper с исходником. На распакованных корнях запущен
настоящий `sheepfold-runtime-hardening`, оба завершились с exit 0.

## Повторение

Рабочий каталог — корень проекта, оболочка POSIX sh/Linux. Нужны Node.js, Python 3,
обычные файловые утилиты, curl/openssl для дополнительного HTTPS-стенда. Тесты
перенаправляют абсолютные пути в уникальные `.build`-каталоги. Не запускайте
производственный helper непосредственно на рабочей машине вместо теста.

```sh
node scripts/run-test-category.mjs --file yandexDownloadRuntime.test.mjs --file yandexDiskRuntime.test.mjs --file yandexUploadRuntime.test.mjs --file yandexSyncRuntime.test.mjs
node scripts/run-test-category.mjs --file changeImpact.test.mjs --file testCategories.test.mjs --file logStorage.test.mjs --file portableShellAndStatus.test.mjs --file packageHardeningRuntime.test.mjs
python scripts/build-test-ipk.py --variant all --out-dir .build/r321-packages
SHEEPFOLD_TEST_IPK="$PWD/.build/r321-packages/luci-app-sheepfold-family-internet-control_0.1.0-321_all.ipk" node scripts/run-test-category.mjs --file testIpkPermissions.test.mjs
SHEEPFOLD_TEST_IPK="$PWD/.build/r321-packages/luci-app-sheepfold-ai-support_0.1.0-321_all.ipk" node scripts/run-test-category.mjs --file testIpkPermissions.test.mjs
node scripts/checkDocumentation.mjs --git HEAD~1
git diff --check
```

Ожидается exit 0 у исправленной версии. Ошибка проверяемой операции внутри теста
должна приводить к сохранению прежнего файла и единственному корректному JSON,
а не к отключению assertion. POSIX symlink/FIFO-сценарии на Windows помечены skip;
это не подтверждение их исполнения.

`SHEEPFOLD_YANDEX_DOWNLOAD_EVIDENCE_DIR` включает экспорт JSON-трасс.
`SHEEPFOLD_YANDEX_TEST_SOURCE` указывает на отдельный каталог со сравниваемым
`sheepfold-yandex-disk`. Источники не изменяются самим fixture. Для воспроизведения
HTTPS распакуйте архив проверок и запускайте его `evidence/httpsDownloadProbe.py`
с `--source` (путь к helper) и `--output` (новый JSON-отчёт). Сертификат, ключ и
временные файлы удаляются после сценария; внешняя сеть не нужна.

## Внешняя проверка семантики и ограничения

Сверены [официальная документация curl](https://curl.se/docs/manpage.html) и
[RFC 9110 §8.6](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.6).
Content-Length в HEAD допустим, но не обязателен; при наличии он должен описывать
размер соответствующего GET. Отсутствие длины приводит к отказу, а не фиктивному
подтверждению. `--max-filesize 0` выключает ограничение; до curl 8.4.0 поведение при
заранее неизвестной длине было слабее. Версия использованного curl записана в HTTPS-отчёте.

Размер не равен checksum. Разные данные одинаковой длины не обнаруживаются.
Нет серверного snapshot, ETag/условного GET, общей блокировки writers, fsync,
квоты RAM и гарантии очистки после SIGKILL. Старый файл может быть изменён другим
привилегированным процессом после последней проверки. Поддержка конкретного
WebDAV-сервера и целевой сборки BusyBox требует отдельной проверки.

Новые SDK/Android-сборки, установка на роутер, физический Android и восстановление
после потери питания не выполнялись. XML/quota/prune, `list` и `restore-config`
остаются R15. Этот отчёт не означает, что исходящие архивные проходы или очистка
облака теперь полностью исправны.
