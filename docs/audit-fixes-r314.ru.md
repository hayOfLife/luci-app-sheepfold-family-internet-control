# Аудит r314: WebDAV-запросы и статус Яндекс Диска

Дата: **12 сентября 2026 года**. Исходная версия: **r313, `111109a`**,
потомок принятой `bdb3a92`. Результат — локальная `main`, пакет **0.1.0-314**.
GitHub, реальные облачные файлы и роутер не изменялись. Новые карточки
**B106–B108** находятся в [накопительном реестре](bug-register.ru.md) — всего 108.

## Область и фактический результат

Изменён только один производственный скрипт: `sheepfold-yandex-disk`.
Исправлены граница аргументов PROPFIND, проверка результата curl/HTTP, диагностический
probe и побочный commit при просмотре. Отдельный preflight архивной отправки больше
не зависит от исторического `authorized`. Изменения Google Drive из r304–r313,
Android, правила доступа D01, UCI defaults, workflow и runner не переписывались.
Новых runtime-зависимостей и перехода с WebDAV на REST нет.

### B106: лишнее сетевое назначение и непроверенный HTTP

На неизменённой r313 trace настоящего shell-вызова показывает `-H`, `Depth:`, `1`,
URL отдельными аргументами. Для Depth 0 лишним назначением оказывается `0`.
Модель curl фиксирует два URL и пустое значение заголовка. Реальной отправки
секретов постороннему серверу не было: модель не выполняет сетевые обращения.

Helper теперь получает число 0/1, передаёт целый `Depth: N` и один URL. `-q`
отключает curlrc, `-g` — globbing самого curl; разрешён HTTPS без отключения TLS.
Тело возвращается только после успешного curl и HTTP 207. При отказе оно не
передаётся reader. Неуспешное чтение квоты больше не превращается в свободное место.

**Граница:** правильный транспорт не делает правильным построчный XML-parser.
Размеры, обе папки, отдельные propstat и полнота поиска остаются R15.

### B107: ложное подтверждение входа и повреждённый JSON

Команда `test` r313 возвращает успех для 301/302. При curl exit 28 и stdout `000`
она выдаёт недопустимое JSON-число `000000`. При неуспешном UCI частичные реквизиты
могут попасть в запрос. Эти три сценария воспроизводятся без изменения production-кода.

Теперь общий probe проверяет код завершения, формат HTTP-кода и 207. Redirect
не выполняется и не объявляется успешным входом. Ошибки curl дают JSON с числом 0;
401/403 сохраняют `auth_failed`. Реквизиты читаются с проверкой exit до запроса.
Проверка TLS не ослаблена. Успешный 207 остаётся **транспортной пробой**, а не
полной проверкой каждого свойства или доказательством права на запись.

### B108: просмотр сохранял чужой черновик

Модель UCI различает сохранённые значения и pending-очередь. До status сохранено
`block_all=0`, в черновике — `1`. Прежний `uci commit sheepfold` переводит 1 в
постоянное состояние и очищает очередь. В r314 оба слоя остаются неизменными.
Проверяется состояние, а не только текст скрипта. Фактическое применение к трафику
не проверялось.

Удалены и set, и commit, иначе собственный флаг остался бы в общей очереди.
Сопутствующий archive-push проверяет доступ непосредственно перед подготовкой,
не ожидая записи `authorized` из status. При плохих реквизитах он отказывает до
MKCOL; при выборе другого хранилища не обращается в Яндекс. Успешный preflight
проверяется только до намеренно отказавшего MKCOL: полной рабочей отправки этот
тест не доказывает. Старые upload/restore-дефекты не исправлялись одними объявлениями.

## Воспроизведение

Рабочий каталог — корень checkout. Нужны Node.js 22, Python 3 и POSIX `sh`.
Тест создаёт и удаляет только свои синтетические файлы в `.build/yandex-fixtures`.
Все вызовы curl и UCI перехватываются моделями. Живой роутер, интернет и реальные
реквизиты для этого запуска не нужны и не должны подставляться.

```sh
node scripts/run-test-category.mjs --file yandexDiskRuntime.test.mjs
```

Ожидается exit 0: **36 tests, 36 pass, 0 fail/skip/cancel**. Для просмотра сырых
TAP-результатов допустим `node --test tests/yandexDiskRuntime.test.mjs`.

Для сравнения создать отдельный каталог и выгрузить в него исходный скрипт:

```sh
mkdir -p .build/yandex-baseline-r313
git show 111109a:package/luci-app-sheepfold-family-internet-control/root/usr/libexec/sheepfold/sheepfold-yandex-disk > .build/yandex-baseline-r313/sheepfold-yandex-disk
SHEEPFOLD_YANDEX_TEST_SOURCE="$PWD/.build/yandex-baseline-r313" node --test tests/yandexDiskRuntime.test.mjs
```

На этой версии ожидается ненулевой exit: **26 fail, 10 pass**. Это проверка
трёх групп дефектов, не 26 независимых уязвимостей. Успешные контроли не названы
ошибками. Сравниваются одинаковые конечные assertions без исправления baseline.
Для сохранения следов задана необязательная `SHEEPFOLD_YANDEX_EVIDENCE_DIR`:
в указанном каталоге остаются только синтетические argv, результаты и состояние UCI.

Не запускать сам production backend на рабочем компьютере вместо fixture: другие
его команды могут писать `/etc/config`, удалять архивы и обращаться в облако.
Ошибка отсутствия Python/sh или тайм-аут не считается подтверждённой ошибкой продукта.

совпадает с исходником, режим 0755, runtime-hardening завершился с exit 0. Не запускать
hardening с `/` вместо изолированного rootfs.

Shell проверен через `sh -n` и BusyBox ash; четыре изменённых JavaScript-модуля —
через `node --check`. **ESLint не выполнен:** offline npm вернул ENOTCACHED.
Синтаксическая проверка не заменяет lint. Документационный checker проверил **280 Markdown-файлов**:
ссылки, §-теги, имена тестов, npm-команды и структура прошли проверку.

## Что не закрыто

HTTP и UCI представлены моделями. Native libuci, реальный curl/TLS/WebDAV Яндекса,
OpenWrt-роутер, Android и новые SDK/CI-сборки не проверялись. Пакет не установлен.
Ни один из результатов не подтверждает корректность полного backup/restore.

В R15 перечислены старые XML-readers, размеры/квоты, пропущенные объявления в
upload/list/download/restore, права/снимки локальных данных, полный статус
синхронизации, RAM-границы и конкурирующие операции. Не объявлять право на запись
доказанным одним 207. Между последовательными чтениями credentials/UCI остаются
гонки. Новые ограничения transport не исправляют другие прямые вызовы curl.

## Первичные источники семантики

Исходники проекта и runtime trace являются основаниями находок. Внешние источники
использованы только для толкования транспорта:

- [curl: URL и command-line options](https://curl.se/docs/manpage.html): свободные
  аргументы считаются URL; `-H` получает одно значение, `-q` должен стоять первым,
  `-g` отключает globbing curl. Просмотрено 12.09.2026.
- [RFC 4918, PROPFIND и Multi-Status](https://www.rfc-editor.org/rfc/rfc4918.html):
  ответ 207 требует отдельной проверки статусов свойств; правильный HTTP-код не
  доказывает всю XML-модель. Это ограничение сохраняется, а не скрывается в probe.
- [Документация Яндекса: WebDAV](https://yandex.ru/dev/disk/webdav/): внешний сервис
  предоставляет WebDAV-интерфейс. Доступ аккаунта и поддержка конкретной прошивки
  по веб-странице не подтверждаются.
