# Установка AdGuard Home из Sheepfold

<!-- §aghinst -->

Документ для разработчика и администратора: что делает кнопка «Установить AdGuard Home»
во вкладке «Интеграция», почему она может быть недоступна и как проверять восстановление.
Код входит в исходники r327; установка на живом OpenWrt и перезапуск вместе с Podkop
этим изменением **ещё не проверены**. Перед выпуском необходим отдельный стенд.

## Согласие и учётная запись

Кнопка сначала открывает подтверждение с DNS-цепочкой, журналированием, риском общего
пароля и резервной копией. Просмотр вкладки ничего не устанавливает. Несохранённые
настройки блокируют запуск. Закрытие окна прекращает только опрос, не worker на роутере.

По явному решению владельца новая учётная запись AdGuard Home имеет логин `admin`
и общий начальный пароль `password`. Это публичные стартовые данные, не секрет проекта.
Любой имеющий сетевой доступ к панели может воспользоваться ими. Установщик не считает
их безопасным постоянным паролем; предупреждение предлагает сменить их в AdGuard Home
и затем обновить данные интеграции Sheepfold. Пароль OpenWrt никогда не копируется.
Панель в этом профиле использует HTTP, не TLS: вход из браузера не шифруется. Для
недоверенной локальной сети профиль не подходит без отдельной настройки HTTPS.

В OpenWrt должен быть задан root-пароль: проверка пустого/заблокированного значения
закрывает установку. Наличие хеша не доказывает, что владелец сменил известный заводской
пароль; определять это по списку «популярных паролей» установщик не пытается.

Ранее настроенный AdGuard Home не перезаписывается: наличие пакета, службы, процесса, бинарного файла,
UCI-конфига, стандартного каталога или файла конфигурации блокирует действие. Старый
каталог операции тоже блокирует повторный запуск до ручного разбора.

## Поддерживаемый профиль

Первый профиль намеренно ограничен AGH **0.107.79, schema 34**, одной службой dnsmasq,
статическим `network.lan`, уже отключённым IPv6 и `/tmp` в tmpfs с `/var -> /tmp`.
Порт dnsmasq до установки должен быть 53. Порты 3000, 5354 и 5355 должны быть свободны.
Установщик не выключает IPv6 сам и не меняет другие сетевые интерфейсы.

Кроме версии бинарника требуется современный официальный init с `config_file` и
непривилегированным пользователем `adguardhome`. Старый OpenWrt 24.10 init с `config`
и запуском от root не подходит: пакет может остаться установленным, но DNS не меняется.
Один общий package-manager ещё не означает проверенную совместимость двух прошивок.

Порог: минимум **128 МиБ MemAvailable и 48 МиБ свободного места** на файловой системе
`/etc`. Это консервативный допуск, а не измеренный предел RAM AdGuard Home и не гарантия
работы на любом 256-МиБ роутере. Размеры правил меняются; тяжёлые дополнительные списки
не устанавливаются. Сам пакет загружается только после подтверждения через общий
`sheepfold-package-manager`; IPK/opkg и OpenWrt APK используют одну логику.

Если `/etc/init.d/podkop` существует, он должен работать, а dnsmasq должен иметь
единственный upstream `127.0.0.42` и `noresolv=1`. Другую схему не преобразуем догадками.
Без Podkop сохраняется прежний работающий upstream dnsmasq. Пробный DNS-запрос перед
установкой и после неё использует `ya.ru` для ru/by, `baidu.com` для cn, иначе `example.org`.
Отказ этой проверки не доказывает отсутствие интернета вообще.

```text
LAN-клиент -> AdGuard Home :53 -> dnsmasq 127.0.0.1:5354
                                  -> прежний upstream
                                  -> Podkop 127.0.0.42:53, если он установлен
```

- DNS AGH слушает только loopback и выбранный LAN IPv4; панель HTTP слушает LAN IPv4:3000.
- DHCP остаётся в dnsmasq; в LAN меняется только выдаваемый DNS (option 6), прочие DHCP-опции сохраняются.
- Кэши dnsmasq и AGH, включая optimistic cache, выключены; fallback/bootstrap AGH пусты.
- Включены только HaGeZi LIGHT и TIF MINI, обновление раз в сутки, лимит одного ответа 16 МБ.
- Safe Browsing, parental control, Safe Search, blocked services и AGH DHCP выключены.
- Журнал AGH: до 1000 запросов в RAM, без файла; статистика за сутки в RAM. Это отдельный
  журнал стороннего AGH, не переключатель личных AI-логов Sheepfold; согласие на него
  содержится в установочной модалке. После перезагрузки эти данные исчезают.
- Конфигурация постоянная: `/etc/adguardhome/adguardhome.yaml`; рабочие данные в `/tmp/adguardhome`.
  Списки после перезагрузки скачиваются заново, до загрузки защита ими не гарантирована.
- Интерфейс AGH: русский язык и автоматическая тема.

Не меняются Podkop, его маршруты/метки/внешний DNS, firewall, Tailscale и системный журнал.
Не копируются настройки буферов NanoPi. Сам официальный пакет OpenWrt может включать
свой init, UCI defaults и sysctl-файл; это свойства пакета, а не обещание отсутствия
побочных действий его postinst. Установщик не открывает WAN-порты, но не отменяет
уже существующие пользовательские правила доступа или пробросы.

## Устройство операции

Исходники: `sheepfold-adguard-install`, `adguard-install-profile.json` и LuCI-модуль
`features/integrations/install.js`. Команды `adguard-install-status` и
`adguard-install-start confirmed` проходят через действующий LuCI router-control.
Нового Android/API endpoint нет. Фоновый worker удерживает общий flock этого установщика.

1. Повторно проверяет условия и DNS, сохраняет проверенные копии `dhcp`, `sheepfold`,
   `network` в `/etc/sheepfold/adguard-install` с закрытыми правами.
2. До установки пакета создаёт закрытую bootstrap-конфигурацию: GUI и DNS только
   loopback, невозможный пароль `!`. Это не даёт postinst открыть первоначальный мастер.
   Закрываются оба официальных пути, включая прежний `/etc/adguardhome.yaml`;
   при завершении старый файл удаляется только если он побайтово равен нашей заглушке.
3. Устанавливает официальный пакет, останавливает его и проверяет точную версию.
4. Формирует новый конфиг через jshn в JSON, который AGH читает как YAML. Чужой YAML
   не парсится и не редактируется. Готовый bcrypt-хеш публичного пароля проверен
   штатной авторизацией AGH; Python/bcrypt и временный мастер на роутере не нужны.
5. Валидирует конфиг `AdGuardHome --check-config`, готовит UCI в отдельном каталоге,
   проверяет отсутствие новых pending changes и совпадение с резервными копиями.
6. Заменяет только собственные подготовленные файлы через проверенный временный
   файл и rename. Перезапускает DNS, проверяет авторизованный API и разрешение имён
   через loopback/LAN; только затем публикует настройки интеграции Sheepfold.

Состояния: `ready`, `unavailable`, `starting`, `installing`, `configuring`, `switching_dns`,
`verifying`, `installed`, `installed_filters_pending`, `failed`, `failed_restored`,
`recovery_required`, `interrupted`. Опрос раз в 3 секунды ограничен примерно 9 минутами;
после него интерфейс предлагает обновить страницу, не запускать вторую установку.

`installed` означает загруженные два стартовых фильтра, а не доказанную фильтрацию
телефона. `installed_filters_pending` не считается ошибкой DNS-установки. Оба состояния
требуют отдельной проверки LAN. Статус операции является сохранённым результатом,
не заменяет текущую диагностику интеграции.

## Границы адаптера

`adguard_auto_manage=1` по-прежнему разрешает только один URL-фильтр Sheepfold. Новая
установка является отдельной подтверждённой операцией, а не расширением старого согласия.

Для HTTP панели, установленной здесь, адаптер требует точного совпадения URL с приватной
квитанцией `/etc/sheepfold/adguard-install/endpoint` и локального маршрута ядра `dev lo`.
Поэтому после смены LAN адреса старый HTTP URL не получает пароль автоматически.
Другой сервер по-прежнему требует HTTPS; переменные HTTP proxy не получают Basic Auth.
В LuCI сохранение прежнего URL допустимо, но backend заново проверяет его перед запросом.

## Сбой и восстановление

При ошибке до переключения DNS исходные настройки остаются. После переключения worker
останавливает AGH и восстанавливает `dhcp`/`sheepfold` только если они ещё совпадают с
его `*.after`. Чужие правки не затираются. Каталог/симлинк вместо файла отклоняется.
Пакет не удаляется автоматически. Резервная копия остаётся и после успешной установки.

В отличие от RAM-файлов, снимки в `/etc/sheepfold/adguard-install` переживают reboot.
Однако это **не crash-safe транзакция**: обрыв питания между заменами файлов может
потребовать ручного восстановления. После reboot незавершённая операция помечается
`interrupted` по boot ID/PID, не запускается заново и не затирает снимки.

При `recovery_required` или `interrupted` зайдите через локальный LuCI/SSH. Сначала
прочитайте `status`/`reason`, сравните текущие `/etc/config/dhcp`, `/etc/config/sheepfold`
с соответствующими `*.before` и `*.after`. Не выводите конфиги в публичный журнал.
Если текущий файл не равен ни одному снимку, разберите отличия вручную: автоматическое
копирование целого файла может уничтожить новую настройку. После проверки восстановите
только нужные DNS-поля, остановите/отключите AGH и перезапустите dnsmasq. Проверьте DNS
на роутере и клиенте. Не удаляйте каталог операции и не повторяйте установку, пока
не разобраны остатки пакета/конфигурации. Возврат UCI не является удалением пакета.

## Проверки разработчика

Рабочий каталог: корень репозитория Sheepfold. PowerShell с Node.js, Python и Git Bash
либо POSIX shell; установщик напрямую на компьютере не запускать. Fixture изолирует
файлы в `.build` и моделирует пакетный менеджер, procd и подготовку UCI.

```powershell
node --test tests/adguardInstall.test.mjs tests/adguardInstallUi.test.mjs tests/integrationPanelUi.test.mjs tests/luciPersistenceAdapters.test.mjs
node --test tests/adguardIntegration.test.mjs
node --test tests/changeImpact.test.mjs tests/testCategories.test.mjs tests/architectureDecisions.test.mjs
npm.cmd run lint:js
npm.cmd run quality:docs:all
git diff --check
```

Ожидается exit 0: согласие/draft/polling, предварительные запреты, отказ пакета, успешная
транзакция, возврат DNS, сохранение чужих правок и ограниченное локальное HTTP-исключение.
Сетевой fake-server AdGuard выполняется отдельным файлом, не вместе со всем набором.
Эти проверки не исполняют настоящий opkg/apk, procd, jshn и DNS-путь телефона.
`spawn EPERM` или timeout fixture не являются результатом теста продукта; следуйте
[инструкции окружения](agent-environment.ru.md), не ослабляйте assertions.

При проверке r327 профильные installer/UI, LuCI, packaging и документационные проверки
прошли. Общий старый `adguardIntegration.test.mjs` остановлен после 11 успешных сценариев
из-за длительности Windows-стенда; это не полный зелёный прогон файла. Перед выпуском
выполнить оставшиеся проверки на подходящем стенде, а не ссылаться на эту частичную запись.

Ручной native smoke принимает абсолютный путь к официальному бинарному AGH 0.107.79
для ОС компьютера, не устанавливает службу, использует случайные loopback-порты и
отключает скачивание фильтров. Пример Windows из корня этого checkout:

```powershell
node tools/router-testing/adguardNativeProbe.mjs C:/Users/User/Documents/pesochnica/sheepfold-r297-review/.build/adguard-native/AdGuardHome/AdGuardHome.exe
```

Ожидаются `PASS profileSchema`, `PASS bootstrapAuthClosed`, `PASS configuredAuth` и exit 0
после удаления fixture. Проверенный Windows release ZIP имел SHA-256
`e42294dc26b2c0d8f4576a91f09aa5129ffdfb7b647026fac77f0abac9acffce`.
На текущем Windows-стенде все три проверки прошли, но очистка созданных AGH БД вернула
`EPERM`, поэтому общий exit был 1. Скрипт показывает оставшийся путь, останавливает свои
процессы и не меняет ACL/антивирус. Не выдавать такой прогон за полный успех. Не передавать
ему бинарник другой архитектуры или рабочий конфиг AGH.

Перед релизом отдельно: чистые OpenWrt 24.10/opkg и 25.12/apk с доступной нужной версией
AGH, сохранность Podkop после reload/reboot, DNS с телефона, LAN/WAN доступность панели,
сбой скачивания списков, пик RAM/места и отключение питания во время переключения.
Требуется доступ восстановления к стенду; основной домашний роутер для этого не использовать.
